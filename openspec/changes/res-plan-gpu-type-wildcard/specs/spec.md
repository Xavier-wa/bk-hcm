# res-plan-device-match

## ADDED Requirements

### Requirement: 先认 GPU 类再比较卡类型

系统 SHALL 在通配判定时先判断机型是否为 GPU 类，再读取 GPU 卡类型。GPU 类 MUST 仅由技术分类判定：`推理GPU`、`训练GPU` 或 `GPU-其他`。不得用机型族判断 GPU 类。展示值「无」与空值 MUST 都视为不是真实卡，不得当作一种卡型号，也不得回退技术分类 + 核心类型。技术分类不是上述 GPU 类时，MUST 按非 GPU 类处理。GPU 类机型 MUST NOT 回退技术分类 + 核心类型。

#### Scenario: 技术分类为推理 GPU 进入卡类型比较

- **WHEN** 两条机型技术分类均为 `推理GPU`，且双方 `gpu_type` 均为真实卡型号
- **THEN** 系统 SHALL 进入卡类型比较，不得仅因技术分类相同就判定可通配

#### Scenario: 展示值「无」不是卡型号且不可通配

- **WHEN** 两条 GPU 类机型的 `gpu_type` 都为「无」，且技术分类与核心类型相同
- **THEN** 系统 SHALL 判定不可通配，不得因「无」=「无」或技术分类相同而通配

#### Scenario: 技术分类非 GPU 类按非 GPU 处理

- **WHEN** 机型技术分类为空或不是 `推理GPU`/`训练GPU`/`GPU-其他`，即使机型族为 `GPU型`
- **THEN** 系统 SHALL 不按 GPU 类处理，走非 GPU 口径

### Requirement: GPU 类按卡类型通配

当两条机型均为 GPU 类，且双方 `gpu_type` 都是真实卡型号（非空、非「无」）时，系统 SHALL 仅按卡类型原文是否全等决定通配。卡类型相同 MUST 判定可通配，即使机型族不同。卡类型不同 MUST 判定不可通配，即使技术分类与核心类型相同。系统 MUST NOT 做卡类型别名合并。

#### Scenario: 同卡类型可跨机型族通配

- **WHEN** 两条机型均为 GPU 类，`gpu_type` 同为 `NVIDIA A100`，机型族不同
- **THEN** 通配结论为可通配

#### Scenario: 不同卡类型即使同族也不可通配

- **WHEN** 两条机型均为 GPU 类，技术分类与核心类型相同，`gpu_type` 分别为 `NVIDIA A100` 与 `V100`
- **THEN** 通配结论为不可通配

#### Scenario: 卡类型原文不全等视为不同

- **WHEN** 两条 GPU 类机型的 `gpu_type` 分别为 `A100` 与 `NVIDIA A100`
- **THEN** 通配结论为不可通配

### Requirement: GPU 类不得回退现网口径

当任一侧为 GPU 类时，系统 MUST NOT 用技术分类 + 核心类型判定通配。一侧为 GPU 类且持有真实卡、另一侧为非 GPU 类时，MUST 判定不可通配（同名除外）。一侧为真实卡、另一侧为「无」时，MUST 判定不可通配，并按入口对非真实卡一侧报错或告警。

#### Scenario: 有卡 GPU 与「无」不可通配

- **WHEN** 一条为 GPU 类且 `gpu_type` 为 `NVIDIA A100`，另一条为 GPU 类且 `gpu_type` 为「无」，即使双方技术分类与核心类型相同
- **THEN** 通配结论为不可通配；仅当「无」一侧是当前操作对象时 MUST 报错

#### Scenario: GPU 与非 GPU 不可通配

- **WHEN** 一条为 GPU 类且持有真实卡，另一条为非 GPU 类，双方技术分类与核心类型相同但机型名不同
- **THEN** 通配结论为不可通配

### Requirement: GPU 类非真实卡时按入口分流

当机型已判定为 GPU 类，但 `gpu_type` 为空或为「无」（都不是真实卡）时：该机型 MUST NOT 与任何其他机型通配（包括另一台同样非真实卡的 GPU 机型），MUST NOT 按技术分类通配。仅当用户正在申领、回收或升降配校验的**目标机型**自身非真实卡时，系统 MUST 失败并返回「GPU 类机型缺少真实卡类型」。预测列表展开、可用机型列表、以及池中其它脏 GPU MUST 只记录告警并退出通配，不得让其余记录或其它机型申领失败。

#### Scenario: 目标机型非真实卡时申领校验报错

- **WHEN** 用户申领、回收或升降配校验的目标机型为 GPU 类且 `gpu_type` 为空或为「无」
- **THEN** 本次操作失败并返回「GPU 类机型缺少真实卡类型」，不按技术分类通配

#### Scenario: 池中脏 GPU 不拖垮其他机型申领

- **WHEN** 预测池中存在 GPU 类且卡类型为空或为「无」的机型，用户申领的是另一台卡类型真实的机型
- **THEN** 脏机型不参与通配，本次申领 MUST 继续按其余可通配机型扣减

#### Scenario: 列表展开遇到非真实卡告警且不通配

- **WHEN** 机型为 GPU 类且 `gpu_type` 为空或为「无」，预测列表展开或可用机型列表做通配
- **THEN** 该机型不出现在其他机型的通配明细中，并留下告警，页面或接口其余结果仍可返回

#### Scenario: 两个非真实卡 GPU 机型也不得互配

- **WHEN** 两条均为 GPU 类且 `gpu_type` 都为空，或都为「无」
- **THEN** 二者不得标为可通配；仅当其中一台是当前操作的目标机型时 MUST 报错

### Requirement: 非 GPU 类保持现网通配

当两条机型都不是 GPU 类时，系统 SHALL 不读取卡类型做相等判断，MUST 仅按技术分类 + 核心类型判定，结论与改造前一致。同名机型 MUST 仍视为可通配。

#### Scenario: 非 GPU 同口径可通配

- **WHEN** 两条均为非 GPU 类，技术分类与核心类型相同
- **THEN** 通配结论为可通配，与改造前一致

#### Scenario: 非 GPU 核心类型不同不可通配

- **WHEN** 两条均为非 GPU 类，核心类型不同
- **THEN** 通配结论为不可通配

#### Scenario: 同名机型始终可通配

- **WHEN** 参与比较的两条机型名称相同
- **THEN** 通配结论为可通配，不进入卡类型或技术分类比较

### Requirement: 四处入口同一通配口径

申领扣减、回收、升降配校验、预测列表展开 MUST 使用同一套通配规则。同一对机型在申领扣减与预测列表展开中的可通配结论 MUST 一致。列表展开对 GPU 非真实卡用告警 + 不通配，申领等用报错，二者结论都是不能通配，只是表现不同。本期 MUST NOT 新增对外通配接口或权限点。

#### Scenario: 同卡 GPU 在申领与列表结论一致

- **WHEN** 同一对 GPU 类机型卡类型相同
- **THEN** 申领扣减与预测列表展开都认定为可通配

#### Scenario: 无对应权限仍被拒绝

- **WHEN** 无对应业务权限的调用方查询预测或提交申领
- **THEN** 请求被拒绝，与改造前一致
