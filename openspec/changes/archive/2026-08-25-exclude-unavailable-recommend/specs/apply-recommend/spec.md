## ADDED Requirements

### Requirement: 离线聚合前过滤当前不可申领的机型组合

系统 SHALL 在自研云（vendor: tcloud-ziyan）离线推荐统计将已交付设备记录按 `(require_type, region, device_type, image_id)` 聚合并写入推荐表之前，对每条记录做机型组合判定。该判定 MUST 调用与申请单共用的同一个方法 `CheckDeviceType`。调用方 SHALL 只传入需求类型与机型主数据，SHALL NOT 传入绿通 logics；绿通配置读取 MUST 由该方法内部按需完成。申请单 SHALL 对本请求需求类型调用一次。离线 SHALL 按需求类型带上该类型实际出现的机型调用 `CheckDeviceType`，SHALL NOT 用全量机型对每个需求类型做笛卡尔积判定；绿通配置仍至多读取一次。申请单 SHALL 保留原有机型查询与现网错误文案。CVM 生产提单 SHALL NOT 因本期改动。口径为 Q1=B，判定 MUST 覆盖：

1. 需求类型为小额绿通或滚服，且机型为特殊型（`DeviceTypeClass == SpecialType`）时 MUST 判定为不可用。
2. 需求类型为小额绿通，且绿通机型政策开关为打开，且机型族不在当前白名单内，或 CPU 核数大于当前上限时 MUST 判定为不可用。绿通允许的机型族与 CPU 上限 MUST 取自当前运营配置 `CvmApplyConfig`，SHALL NOT 写死「永远标准型 / 永远 16 核」。
3. 绿通机型政策开关关闭时，MUST NOT 再用「机型族 + 核数上限」卡住绿通记录；「禁止特殊型」对绿通、滚服 MUST 仍然生效。
4. 离线路径下，机型在机型主数据中不存在时 MUST 视为不可用，SHALL NOT 写入残缺机型。申请单 SHALL 维持原行为：只校验查询命中的机型。

判定为不可用的记录 MUST 直接跳过：不参与用户维度与业务维度计数，不写入 `ziyan_cvm_apply_user_recommend` / `ziyan_cvm_apply_biz_recommend`，SHALL NOT 替换机型、SHALL NOT 改 Top-K 排序键。本过滤 MUST NOT 修改 `ziyan_cvm_device_info` 源表。

常规项目、春节保障、机房裁撤、春保资源池、短租 MUST NOT 因「绿通机型族 + 核数」规则被本过滤剔除；若其机型是特殊型但需求类型不是绿通/滚服，MUST NOT 因禁止特殊型被本过滤剔除。

机型主数据与绿通机型政策 MUST 按本轮离线任务 / 单次申请单请求批量读取（机型主数据按页批量查询，绿通配置按需至多一次；均发生在聚合循环之外，避免对每条历史记录各打一次）。读取绿通政策配置失败、批量查询机型信息失败时，本轮离线任务 MUST 失败，SHALL NOT 写入半成品推荐数据。申请单路径 I/O 失败 MUST 同样返回 error。

被跳过的记录 MUST 逐条输出 Warn 级别日志，内容 MUST 包含记录标识、需求类型、机型、剔除原因（不支持特殊机型 / 机型族 {family} 不在允许范围 / CPU核数 {n} 超过上限 {limit} / 机型数据不存在），以及 rid。系统 SHALL NOT 为此过滤额外输出汇总报表。

某个 (业务, 用户) 或 (业务) 分组在本过滤后无任何候选时，本轮 MUST NOT 为该分组写入任何行（含占位空行）；该分组的历史推荐行 MUST 按既有过期清理规则（`updated_at < 本轮任务开始时间`）删除。

本过滤 MUST 只发生在离线写入侧（Q3=B）。MUST NOT 改变在线读取接口 `ApplyRecommendTop` / `ApplyRecommendByStatic` / `ApplyRecommendByPlan` 的请求与响应结构；MUST NOT 在这些接口的读取/返回路径上增加机型组合过滤。`ApplyRecommendByPlan` 候选不来自推荐表，本期 MUST NOT 为其实现或验收过滤（Q7=A）。静态推荐空列表时接口 MUST 仍返回成功且 `items` 为空数组，SHALL NOT 返回业务错误码，本期 SHALL NOT 改 Agent/页面话术或回退另一条推荐口（Q4 默认）。无新增 IAM / CMDB / ITSM 集成点。

#### Scenario: 小额绿通加政策不允许的机型不写入

- **GIVEN** 绿通机型政策开关已打开，当前允许标准型、CPU 上限为 16；历史交付中存在「小额绿通 + ITA5」
- **WHEN** 离线推荐任务执行成功
- **THEN** 两张推荐表中不出现该组合行

#### Scenario: 政策允许的绿通标准型照常写入

- **GIVEN** 绿通机型政策开关已打开，当前允许标准型、CPU 上限为 16；历史交付中存在「小额绿通 + 某标准型且核数 ≤ 16」
- **WHEN** 离线推荐任务执行成功
- **THEN** 该组合照常聚合并写入推荐表

#### Scenario: 绿通或滚服加特殊型不写入

- **GIVEN** 历史交付中存在「小额绿通 + 特殊型」或「滚服 + 特殊型」
- **WHEN** 离线推荐任务执行成功
- **THEN** 这些记录不写入推荐表

#### Scenario: 滚服加非特殊型不被本过滤剔除

- **GIVEN** 历史交付中存在「滚服 + 非特殊型」
- **WHEN** 离线推荐任务执行成功
- **THEN** 该记录不被本机型组合过滤剔除（仍可按既有滚服规则写入；是否被读侧滚服规则丢掉不在本期改）

#### Scenario: 同组混合候选只保留可用组合

- **GIVEN** 同一分组下同时有可用绿通组合与 ITA5 绿通组合
- **WHEN** 离线推荐任务执行成功
- **THEN** 表中只保留可用组合，不出现占位行，ITA5 也不被替换成其他机型

#### Scenario: 整组被过滤不写入占位行

- **GIVEN** 某 (业务, 用户) 分组下全部历史记录都未通过机型组合校验
- **WHEN** 离线推荐任务执行成功
- **THEN** 该分组本轮不写入任何行，历史行在过期清理后被删除

#### Scenario: 申请单与离线调用同一个判定函数

- **GIVEN** 申请单与离线写入共用 `CheckDeviceType`
- **WHEN** 两处分别处理同一组（需求类型, 机型）且机型主数据可命中
- **THEN** 两边都调用该同一方法；允许与不允许的结论一致
- **AND** CVM 生产提单不因本期改动

#### Scenario: 与申请单对不允许组合结论一致

- **GIVEN** 同一组「小额绿通 + ITA5」
- **WHEN** 分别走申请单机型组合校验与离线过滤
- **THEN** 两边都判定为不允许；推荐表不出现该行，申请单也不接受该组合

#### Scenario: 与申请单对允许组合结论一致

- **GIVEN** 同一组「小额绿通 + 政策允许的标准型机型」
- **WHEN** 分别走申请单校验与离线过滤
- **THEN** 两边都判定为允许；该组合写入推荐表，申请单也接受该组合

#### Scenario: 下一轮任务后静态推荐结果干净且预测推荐不改

- **GIVEN** 离线任务已按新规则重建推荐表
- **WHEN** 调用静态推荐 `ApplyRecommendByStatic`
- **THEN** 返回项均能通过当前机型组合校验，接口请求与响应结构不变；本期不改、不验收预测推荐 `ApplyRecommendByPlan` 的过滤行为

#### Scenario: 静态推荐空列表仍成功

- **GIVEN** 推荐表已被覆盖且某次静态推荐候选全部被写侧滤掉
- **WHEN** 调用静态推荐
- **THEN** 返回成功且 `items` 为空数组，不返回业务错误码

#### Scenario: 源表记录不被修改

- **GIVEN** 任务执行完成
- **WHEN** 查询 `ziyan_cvm_device_info`
- **THEN** 源表记录数与机型、需求类型均未被修改

#### Scenario: 政策开关关闭时仍禁止特殊型

- **GIVEN** 绿通机型政策开关关闭，历史交付中存在「小额绿通 + 非白名单机型但非特殊型」以及「小额绿通 + 特殊型」
- **WHEN** 离线推荐任务执行成功
- **THEN** 前者不被「机型族 + 核数」规则剔除；后者仍因禁止特殊型被剔除

#### Scenario: 离线对机型主数据缺失视为不可用

- **GIVEN** 一条记录的机型在机型主数据中不存在
- **WHEN** 离线推荐任务执行
- **THEN** 该记录被剔除且不写入推荐表，并输出含「机型数据不存在」原因的 Warn 日志

#### Scenario: 非绿通滚服需求类型不受本过滤误伤

- **GIVEN** 历史交付中存在常规项目（或春节保障 / 机房裁撤 / 春保资源池 / 短租）且机型为特殊型或不在绿通白名单内
- **WHEN** 离线推荐任务执行成功
- **THEN** 这些记录不被本机型组合过滤剔除

#### Scenario: 配置或机型查询失败则本轮任务失败

- **GIVEN** 本轮读取绿通政策配置失败，或批量查询机型信息失败
- **WHEN** 离线推荐任务执行
- **THEN** 本轮任务失败，不写入半成品推荐数据

#### Scenario: 被剔除记录逐条 Warn

- **GIVEN** 历史交付中存在至少一条因特殊型、机型族不在允许范围、CPU核数超过上限或机型数据不存在而被剔除的记录
- **WHEN** 离线推荐任务执行
- **THEN** 每条被剔除记录均有一条 Warn 日志，内容包含记录标识、需求类型、机型、剔除原因与 rid

#### Scenario: 在线读路径不增加过滤

- **GIVEN** 新版本已部署但下一轮离线任务尚未成功覆盖推荐表
- **WHEN** 调用 `ApplyRecommendByStatic` / `ApplyRecommendTop` / `ApplyRecommendByPlan`
- **THEN** 这些接口的读取逻辑不增加机型组合过滤；存量旧组合仍可能被静态推荐打出，直到下一轮任务或手动同步成功

#### Scenario: 离线循环内不打机型或配置远程

- **GIVEN** 本轮已交付记录中存在多条绿通或滚服记录
- **WHEN** 离线推荐任务执行
- **THEN** 机型主数据按页批量查询与绿通配置读取均发生在聚合循环之外；绿通配置至多读取一次
