## Context

HCM 自研云机型同步当前已从 CRP 接口拉取机型数据并写入 `device_type` 表，但在资源对冲预测场景中，缺乏统一的技术分类资源量度量标准。不同技术分类的机型需要采用不同的资源当量计算方式：

- 内存型机型应以内存容量作为资源量
- 高IO型/大数据型机型应以磁盘总容量作为资源量
- 其他机型（含未知分类）应以前缀CPU核数作为资源量

当前 `device_type` 表未记录这一指标，导致下游预测准确性不足。需要在同步时自动计算并存储该技术分类资源量。

项目已集成 openspec 命令，需按规范生成完整的变更提案工件。

## Goals / Non-Goals

**Goals:**

- 为 `device_type` 表新增 `tech_class_res_amt` 字段（DECIMAL(10,2)，默认 0）
- 在自研云机型同步时，按技术分类自动计算资源量并赋值
- 全链路适配新字段：数据层、接口层、Core 层、同步层
- 补齐 CRP 接口返回结构体缺失的磁盘信息字段
- 新增资源量计算函数，支持内存型、高IO型/大数据型、其他类型的差异化计算
- 磁盘信息异常时打印告警日志并 fallback 到 CPU 核数

**Non-Goals:**

- 不涉及腾讯云机型同步（后续单独处理）
- 不修改 `woa_device_type` 表（自研云同步不操作该表）
- 不新增对外接口，仅扩展现有查询接口返回字段
- 不改变现有同步流程的触发机制和调度逻辑

## Decisions

### 1. 数据库字段默认值为 0 而非 NULL

**决策**: `tech_class_res_amt` 字段默认值为 0，不使用 NULL。

**理由**:

- 避免 Go 结构体使用指针处理 NULL 场景，简化代码逻辑
- 历史数据该字段默认为 0，不影响现有功能
- 0 值具有明确语义：表示未计算或资源量为 0

**备选方案**:

- 使用 NULL 作为默认值 —— 被否决，增加代码复杂度

### 3. 资源量计算采用差异化规则，未知分类 fallback 到 CPU 核数

**决策**: 根据 `CvmInstanceTypeClass`（技术分类）采用不同计算规则：

- 内存型：取 `RamAmount`（单位 GB）
- 高IO型、大数据型：取 `DiskBlockNum * DiskBlockSize / 1024`（单位 TB）
- 其他所有场景（含未知分类、空值、磁盘异常）：fallback 到 `CPUAmount`

**理由**:

- 内存型机型的核心资源是内存，应以内存容量衡量
- 高IO型/大数据型机型的核心资源是磁盘，应以磁盘总容量衡量
- 其他机型（含计算型、通用型等）以前缀CPU核数衡量
- Fallback 策略保证计算函数健壮性，避免异常数据导致同步失败

**备选方案**:

- 所有分类统一使用 CPU 核数 —— 被否决，无法体现不同技术分类的资源特征
- 未知分类报错退出同步 —— 被否决，过于严格，影响同步稳定性

### 4. 磁盘信息异常时打印告警日志并继续同步

**决策**: 当高IO型/大数据型机型的磁盘信息缺失或异常时，打印 Warn 级别日志，并 fallback 到 CPU 核数。

**理由**:

- 防御性编程，避免异常数据导致同步中断
- Warn 日志便于运维人员发现数据质量问题
- Fallback 到 CPU 核数保证同步流程继续

**备选方案**:

- 磁盘异常时跳过该条机型数据 —— 被否决，会导致数据缺失
- 磁盘异常时报错退出同步 —— 被否决，过于严格

### 5. 浮点数比较使用误差容忍度 0.01

**决策**: 在变更检测时，使用 `math.Abs(a-b) > 0.01` 判断 `tech_class_res_amt` 是否发生变化。

**理由**:

- `DECIMAL(10,2)` 字段精度为 2 位小数
- 使用 0.01 的误差容忍度，避免因浮点数精度问题导致误判
- 符合业务场景：资源量变化小于 0.01 可认为是同一值

**备选方案**:

- 直接使用 `!=` 比较 —— 被否决，浮点数精度问题可能导致误判
- 使用 `math.Abs(a-b) > 0.1` —— 被否决，误差容忍度过大

## Risks / Trade-offs

- **CRP 接口返回的磁盘信息可能不完整** → 已在计算函数中增加防御性判断，磁盘信息异常时 fallback 到 CPU 核数并打印 Warn 日志
- **历史数据该字段为 0，可能与实际资源量不符** → 这是可接受的状态，历史数据可通过重新同步更新
- **`CvmInstanceTypeClass` 返回值语言问题** → 已确认该字段返回中文（内存型、高IO型等），计算函数可直接用中文比对，无需转码
- **新增字段可能导致查询接口返回数据变大** → 仅新增一个字段，影响可忽略
- **变更检测逻辑增加新字段判断，可能影响性能** → 仅增加一个浮点数比较，性能影响可忽略
