### 描述

- 该接口提供版本：v9.9.9.9+。
- 该接口所需权限：业务访问。
- 该接口功能描述：在指定业务下提交当前用户对某一轮 Agent 对话的反馈。本接口按 `run_id` **覆盖更新**：该 run 尚无反馈时插入一行，已有反馈时覆盖同一行，不会再插一条。一个 run 最多一条，点赞与点踩互斥；改判（已赞再踩或已踩再赞）会清空旧的 `tags` 与 `comment` 后再写入本次字段。点赞 / 点踩瞬间、面板补充标签与文本、改判都走本接口。只能写自己的、且属于当前业务的反馈。

### URL

POST /api/v1/agent/bizs/{bk_biz_id}/feedback/commit

### 路径参数

| 参数名称      | 参数类型  | 必选 | 描述      |
|-----------|-------|----|---------|
| bk_biz_id | int64 | 是  | 蓝鲸业务 ID |

### 输入参数

| 参数名称    | 参数类型         | 必选 | 描述                                                                 |
|---------|--------------|----|--------------------------------------------------------------------|
| session_id | string    | 是  | 所属会话 ID，必须是当前用户、当前业务下的会话                                         |
| run_id  | string       | 是  | 本轮对话的 run ID                                                      |
| reaction  | enum string  | 是  | 反馈态度。枚举值：`like`（点赞）、`dislike`（点踩）                                     |
| tags    | string array | 否  | 归因标签，可多选也可不传或传空数组。取值必须是当前 `reaction` 对应 `global_config` 标签 map 的 key |
| comment | string       | 否  | 用户手输文本，选填，上限 500 字符（按字不算字节）                                      |

### 调用示例

点赞瞬间（先落态度，可不带标签与文本）：

```json
{
  "session_id": "s1",
  "run_id": "x9y8z7w6",
  "reaction": "like"
}
```

点踩后补充标签与文本：

```json
{
  "session_id": "s1",
  "run_id": "x9y8z7w6",
  "reaction": "dislike",
  "tags": ["factual_error", "incomplete"],
  "comment": "返回的账号列表和实际不一致"
}
```

### 响应示例

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "00000001"
  }
}
```

### 响应参数说明

| 参数名称    | 参数类型   | 描述   |
|---------|--------|------|
| code    | int32  | 状态码  |
| message | string | 请求信息 |
| data    | object | 响应数据 |

#### data

| 参数名称 | 参数类型   | 描述                                      |
|------|--------|-----------------------------------------|
| id   | string | 反馈表主键。新建时为新 ID，覆盖更新时为该 run 已有行的 ID |

### 错误码说明

| code    | 描述                                                          |
|---------|-------------------------------------------------------------|
| 2000001 | 请求参数错误，例如路径参数 `bk_biz_id` 为空、为 0 或负数，`session_id` / `run_id` / `reaction` 非法，或 `tags` 跨套 / 未知 |
| 2000003 | `session_id` 对应会话不存在                                        |
| 2000006 | 提交反馈失败                                                      |
| 2000012 | 用户无指定业务的「业务访问」权限，或该会话 / 已有反馈不属于当前用户 / 当前业务                     |

### 补充说明

- 该 run 尚无反馈时插入一行；已有反馈时按 `run_id` 覆盖更新，不会再插一行。
- 改判（已有行的 `reaction` 与本次不同）：服务端先清空旧 `tags` / `comment`，再写入本次字段。赞的归因不会留在踩上。
- `session_id` 必传，服务端校验会话属于当前用户且业务与路径一致；`bk_biz_id` 取自路径，请求体不用传。
- `tags` 跨套或未知值（例如 `reaction=like` 却传了 `factual_error`）返回参数非法，不会静默丢弃。
- 对应 `global_config` 标签 map 缺失时，只允许空 `tags`。
