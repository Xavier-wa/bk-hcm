# 视觉与行为校验

校验必须同时对照设计截图和行为上下文。正常态看起来相似，不代表 annotations 定义的交互和异常状态已经还原。

## 一、执行前

先读取仓库规则，并确认脚本、测试、lint、构建、dev server 或浏览器自动化是否需要用户授权。未执行的检查不得描述为通过。

## 二、对齐基准

比较前保持条件一致：

- 相同 viewport、缩放和主题。
- 相同数据、文案和状态。
- 相同字体与资源加载状态。
- Figma 截图来自正确节点和 variant。

条件不一致时先修正基准，不要把环境差异当作实现偏差。

## 三、逐区域视觉检查

| 区域 | 检查项 |
| --- | --- |
| 页面/容器 | 宽高、布局方向、对齐、滚动、背景 |
| 栅格/区块 | 列宽、gap、padding、margin、分割 |
| 控件 | 高度、边框、圆角、状态、图标位置 |
| 排版 | 字体、字号、字重、行高、颜色、基线 |
| 内容 | 换行、截断、空值、长文本、本地化压力 |
| 图形资源 | 形状、尺寸、颜色、比例、裁切 |
| 浮层 | 锚点、偏移、层级、遮罩、关闭入口 |
| 状态 | hover、focus、active、disabled、loading、empty、error、selected |

优先修正结构和布局，再处理间距、排版和装饰差异，避免在错误结构上反复微调像素。

## 四、行为检查

根据 annotations、父级说明和 variants 核对：

- click、hover、focus、键盘和数据触发。
- 状态进入、退出、取消、重试和恢复。
- 表单校验、错误定位和提示关联。
- 已定义的 loading 与重复操作限制。
- 弹层打开/关闭、焦点进入/返回。
- 导航目标、数据提交或删除结果。
- 可访问名称、语义和焦点顺序。

清单中的行为只有设计或项目已有依据时才实现；信息缺失时询问，不为了“覆盖完整”而新增需求。

## 五、响应式

1. 列出设计提供的 viewport/variant。
2. 列出项目已有断点或容器规则。
3. 建立对应关系后验证布局、显隐、换行和交互入口。
4. 设计与项目均未定义关键变化时，暂停并询问。

不要自行增加移动端、平板或超宽屏方案。

## 六、回归范围

- 本次页面或组件的正常态与已定义状态。
- 直接受影响的共享组件使用方。
- 修改过的 Theme、Icon 或公共样式入口。
- 微前端/嵌入场景只在本次改动涉及时验证。

不把窄需求扩大为全站视觉回归。

## 七、交付报告

```text
视觉对照：已检查/未检查，结果与剩余差异
行为状态：已检查/未检查，结果与剩余差异
响应式：已检查的 viewport；未定义或未覆盖项
自动验证：实际执行的命令及结果
未执行验证：命令或场景及原因
阻塞/限制：Figma 权限、运行环境或缺失需求
```

若应用无法运行或 Figma 上下文不完整，要明确说明由此产生的校验边界。
