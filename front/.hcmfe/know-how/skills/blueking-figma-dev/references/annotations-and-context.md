# 标注与画布上下文

Figma 目标节点常只展示正常态的一帧。交互规则、异常状态、红线和内容约束可能位于 annotations、父级 section 或旁边的 variants 中。

## 一、必须收集的信息

| 来源 | 常见内容 | 获取方式 |
| --- | --- | --- |
| 目标节点 | 主结构、Auto Layout、变量引用、参考代码 | `get_design_context` |
| 节点截图 | 视觉层级、对齐、裁切、叠加关系 | `get_screenshot` |
| Annotations | 尺寸、交互、状态机、数据来源、限制条件 | 设计上下文与截图 |
| 父级 frame/section | 红线、旁注、流程说明、多状态对照 | `get_metadata` 后按需截图/下钻 |
| 兄弟 variants | hover、disabled、loading、empty、error 等状态 | 分别读取相关节点 |
| 图层命名 | 状态和语义线索 | `get_metadata`、设计上下文 |
| 示例数据 | 空值、最长文本、换行、截断、本地化压力 | 截图和旁注 |
| Variables | 设计语义与候选值 | `get_variable_defs` |

Figma 变量名只表达设计语义，不证明项目存在同名 Token。

## 二、先大后小取数

1. 大节点先用 `get_metadata` 看页面、section、frame 和 variants 层级。
2. 读取目标节点的 design context。
3. 获取目标节点截图作为视觉基准。
4. 若父级包含标注或状态对照，再获取父级截图。
5. 父级过大时，只下钻相关兄弟 variants。
6. 获取节点实际引用的 variables 与真实图片/SVG。

兄弟节点用于理解意图，不代表全部属于本次实现范围。

## 三、状态翻译表

| 设计线索 | 需要确认的实现信息 |
| --- | --- |
| `hover` / 悬浮 | 触发区域、显示内容、延时、退出方式 |
| `focus` | 键盘焦点、焦点环、焦点顺序 |
| `disabled` | 禁用条件、视觉、是否保留提示 |
| `loading` | 触发时机、覆盖范围、能否重复操作 |
| `empty` | 空数据条件、文案、操作入口 |
| `error` | 错误来源、展示位置、恢复/重试方式 |
| `selected` / `active` | 选择来源、互斥关系、持久化方式 |
| `overflow` | 最大宽度、换行/截断、全文查看方式 |
| `success` | 成功反馈、后续跳转或状态更新 |
| 响应式 variant | 断点、布局变化、隐藏/替换规则 |

对每个交互至少明确：

- 触发：click、hover、focus、keyboard、data 或 viewport。
- 状态：初始、处理中、成功、失败及退出。
- 结果：可见内容、数据变化和导航。
- 恢复：取消、关闭、重试或回滚。
- 可访问性：语义、可访问名称、焦点管理和键盘行为。

只实现设计、产品要求或项目既有行为支持的状态。

## 四、冲突处理

| 情况 | 处理 |
| --- | --- |
| Annotation 与截图冲突 | 明确列出冲突，暂停该决策并询问 |
| 图层命名与视觉语义冲突 | 结合交互和父级上下文，仍不明确则询问 |
| 设计变量与项目 Token 不一致 | 以项目实际接入为准，设计变量仅作语义候选 |
| 主画面缺少必需状态 | 先找 variants/旁注；仍缺失则询问 |
| Figma 生成代码与项目栈不同 | 只取结构和语义，不复制实现 |

## 五、必须停问

- 交互去向、数据变更或撤销规则未说明。
- 必需状态存在但文案、行为或恢复方式未定义。
- 设计要求响应式，但既无 variant 也无项目断点依据。
- 组件、Icon 或资源存在多个合理语义。
- 权限或上下文不完整，无法确认关键事实。

提问必须指出缺失的具体决策。用户未要求选项时，不选择“安全默认值”、不自行设计状态机。
