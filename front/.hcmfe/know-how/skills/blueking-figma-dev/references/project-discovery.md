# 项目侦察

先识别目标 BlueKing Vue 项目的版本、组件体系和现有约定，再翻译设计。

## 一、确认实现位置

先明确：

- 目标文件、目录、package、路由和页面入口。
- 是新增页面、扩展现有组件，还是修改已有状态。
- 哪些文件属于本次需求，哪些业务封装可能直接复用。

目标位置不明确时先询问，不要自行选择目录。

## 二、识别 Vue 与组件库版本

读取目标 package、锁文件、实际 imports、全局注册和相邻组件，确认：

- Vue2 或 Vue3。
- Vue2 的 `bk-magic-vue`，或 Vue3 的 `bkui-vue`，以及精确版本和导入方式。
- 是否安装并实际使用 `@blueking/tdesign-ui`。
- 是否安装并实际使用 `@blueking/search-select-v3`。
- 是否安装并实际使用 `@blueking/date-picker`。

依赖“已安装”不等于目标区域“正在使用”。扩展包必须有实际 import、组件标签、全局注册或稳定业务封装作为证据。不得通过仓库名或固定目录名推断 Vue 版本。

## 三、查找相邻实现

至少阅读：

1. 目标目录内 2–3 个同类页面或组件。
2. 目标设计涉及的业务封装。
3. 同类表单、表格、弹层、空态和错误态的现有实现。
4. 相邻组件的导入方式、命名、组合和编码风格。

优先复用已有模式，避免仅因为 Figma 结构不同就新增第二套实现。

## 四、补齐项目约定

| 维度 | 检查内容 | 主要证据 |
| --- | --- | --- |
| 业务封装 | 已有页面组件、领域组件、扩展点 | 相邻页面、组件目录、实际用法 |
| Icon | BlueKing Icon、iconfont、SVG、资源导出 | imports、Icon 文档、资源目录 |
| Theme | 已加载变量、Sass/CSS 变量、品牌 Token | 样式入口、变量定义、运行时 selector |
| i18n | 文案、日期和数字格式 | 相邻组件、locale 目录 |
| 数据 | store、请求层、路由、错误处理 | 页面逻辑、API 模块、类型 |
| 验证 | 测试、Story、类型检查、构建和运行方式 | scripts、测试文件、CI、项目规则 |

Theme 变量只有在项目已定义并加载时才能使用；Icon export 必须由对应组件 skill 或项目真实资源确认。

## 五、证据职责与优先级

不同证据只决定其负责的事项：

1. 仓库规则和目标目录稳定实现决定业务边界、文件位置与编码约定。
2. 项目 package、锁文件和实际 imports 决定 Vue、组件库及扩展包版本。
3. 项目已有业务封装决定是否优先复用，以及组件的导入和组合方式。
4. 与目标项目版本严格匹配的组件 skill reference 是组件 props、events、slots、methods、类型、默认值、限制和示例的最终依据。
5. `components.md`、版本 map、`icons.md` 和 `theme.md` 只产生候选。
6. Figma variables 和生成代码只提供设计语义与视觉参考。

项目安装源码、类型声明或相邻用法不得在 API 冲突时覆盖组件 skill reference。无法获取或无法从组件 skill 确认组件 API 时，停止并询问，不回退猜测。

## 六、侦察摘要

实施前形成简短内部摘要：

```text
目标位置：
Vue/精确版本：
基础组件库/精确版本/配套组件 skill：
扩展组件包/精确版本/配套组件 skill：
可复用业务组件：
Icon 与资源体系：
Theme：
i18n 与数据约定：
可用验证方式：
必须询问的问题：
```

摘要中的每项都应有文件或代码证据。缺失或矛盾时，暂停对应决策，不用猜测补全。
