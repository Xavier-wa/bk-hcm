# 代码评审准则库

> 本文件是团队的评审共识载体。`bkdevbuddy code-review init` 只生成这份骨架，
> 内容全部由团队自己累积——第一条通常来自第一次真实评审。
>
> 评审时 `code-reviewer` 子代理会读取本文件，逐条对照本次改动；命中即产出 finding
> 并引用准则 id。库为空时评审只会产出 Info 级建议与「准则提议」，这是预期行为。

**怎么加一条**：复制下方模板追加到文件末尾。也可以在评审报告里采纳 AI 的准则提议，
或用 `bkdevbuddy code-review add`。

**格式契约**：二级标题 `## <id> · <标题>` 里的 `<id>` 是准则唯一键（kebab-case），
被 finding 引用、被 stats 计数，**不要改动已有 id**，否则历史数据会断。
第一个二级标题之前的内容视为导言，不参与解析。

**写之前先想两件事**：已安装 rules 覆盖过的规范不要重复写（需要时引用 rule 名即可），
同一知识两处维护必然漂移；只写你真的希望**每次**评审都被检查的事，条目越少越锐利。

## no-private-component-internals · 禁止读写组件未导出的内部状态

**要求**：关闭/打开第三方组件弹层只走文档中的公开方法或 v-model；禁止 as any 读写内部字段。

**为什么**：内部字段名会随版本变，评审若只扫「有没有关下拉」会漏掉这种脆弱实现。

❌ (selectRef.value as any).isPopoverShow = false
✅ selectRef.value?.hidePopover()
