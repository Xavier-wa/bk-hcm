## 1. 需求背景

前两个子迭代已完成业务视角 chatbot 的**路由与布局**（`iter-biz-index-chatbot-route-layout`）和**侧边栏会话列表**（`iter-biz-index-chatbot-session-sidebar`）。本子需求聚焦**主内容区的默认态（首页空态）**：用户进入 chatbot 页且未选中/未开始任何会话时，主内容区展示「快捷操作卡片」，引导用户快速发起常用任务，替代当前单一的空态占位（💬 + 「海垒 AI 助手」+ 「有什么可以帮你的？」）。

## 2. 用户故事

- 作为首次进入 AI 助手的用户，我希望主内容区有「快捷操作卡片」可点，能快速发起常见任务，而不是面对一个空白输入框无从下手。
- 作为日常使用的用户，我希望点击某个快捷卡片后能直接进入对应任务的对话，减少手动输入成本。

## 3. 功能范围

### 3.1 默认主内容区（本迭代必须）

| 项 | 要求 |
|----|------|
| **展示时机** | **仅首页空态**（无选中会话、无消息）时，主内容区展示默认内容（含快捷操作卡片）。切到**已有会话但无消息**时主内容区**保持空白**，不展示默认内容、也不回退基础欢迎态。（Q3 已确认） |
| **标题/欢迎区** | 按新稿调整（Q4 已确认）。主内容区默认内容自上而下为：**欢迎语 + 功能 tips + 大卡片**（具体文案/图标 design 阶段以 Figma 为准）。 |
| **快捷操作卡片** | 首页空态下同时存在**两类卡片**（见 §3.2）：主内容区「大卡片」+ 聊天框上方「一排小卡片」。 |
| **空态收敛** | 用户发送首条消息或切换到已有会话后，主内容区切换为正常对话视图，两类卡片均隐藏。 |

### 3.2 快捷操作卡片（本迭代必须）

本迭代有**两类**快捷操作卡片，行为不同（Q2 已确认）：

| 类型 | 位置 | 点击行为 |
|------|------|----------|
| **大卡片** | 主内容区（欢迎区下方） | **直接发送**一条预设消息，立即开启会话 |
| **小卡片** | 聊天输入框**上方一排** | 把卡片对应文案**填入输入框**，需用户再点一次发送（不自动发送） |

| 项 | 要求 |
|----|------|
| **卡片内容** | 每张卡片至少包含：标题（+ 可选的描述/图标）。具体清单（大卡片/小卡片有哪些、文案）**design 阶段从 Figma 稿提取**（Q1 已确认）。 |
| **卡片来源** | 全业务**统一一套**（Q5）；**前端固定配置**——卡片文案/预设消息写在前端常量，不走接口（Q1 已确认）。 |
| **卡片数量/布局** | 大卡片与小卡片各自的数量、栅格/排布以设计稿为准（design 阶段对齐）。 |

## 4. 非目标（不在本迭代范围）

- 侧边栏会话列表相关交互（已在上一迭代完成）
- 对话流 / 消息区 / HITL / 流式交互改造
- 路由与全局布局调整
- 快捷卡片的后台配置管理能力（如有，另立需求）

## 5. 验收标准

### P0

- [ ] 进入 chatbot 首页空态时，主内容区展示默认内容：欢迎区 + 大卡片，且聊天框上方有一排小卡片。
- [ ] 点击**大卡片**：直接发送预设消息，立即开启会话。
- [ ] 点击**小卡片**：对应文案填入输入框，不自动发送，待用户再点一次发送。
- [ ] 发送首条消息或切换到已有会话后，默认主内容区（大卡片）与小卡片均隐藏，进入正常对话视图。

### P1

- [ ] 「新对话」回到首页空态时，默认主内容区（大卡片）与小卡片重新展示。
- [ ] 进入**已有会话但无消息**时，主内容区保持空白（不展示默认内容、不回退基础欢迎态），不报错不白屏。
