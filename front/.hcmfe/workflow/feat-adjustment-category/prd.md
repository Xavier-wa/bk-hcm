## 需求背景

当前"账单调整"（调账）功能的"资源类别"只有 CPU / GPU 两类，无法区分 GPU 成本的具体构成
（GPU 卡算力 vs 大模型 API 调用费 vs 其它 GPU 支出）。核算运营人员需要在新增/编辑调账时，
把资源类别细分为 **CPU、GPU卡、GPU API、GPU其他** 四类，并在选择 GPU卡/GPU API 时进一步
指定卡型/模型厂商，以便按真实成本性质归集调账金额。

不做的影响：调账数据的 GPU 成本无法按卡型/厂商维度拆分分析，且与已上线的 OBS 账单分类口径
不一致（OBS 侧已按卡型/API拆分）。

后端枚举扩展、字段新增、存量数据迁移、OBS 同步映射等由兄弟单 1069995598136722867 负责，
**本单仅覆盖前端页面改动**。

## 用户故事

1. 作为核算运营人员，我想要在新增调账时把资源类别从 CPU/GPU 二选，改为
   CPU/GPU卡/GPU API/GPU其他四选，以便更精细地标记调账的资源归属。
2. 作为核算运营人员，我想要资源类别选择"GPU卡"时能进一步选择具体卡型，以便按卡型分析
   GPU 算力成本。
3. 作为核算运营人员，我想要资源类别选择"GPU API"时能进一步选择模型厂商，以便按厂商分析
   大模型 API 支出。
4. 作为核算运营人员，我想要卡型/模型厂商以下拉选择而非手工输入，以避免拼写不一致导致成本
   无法归集。
5. 作为核算运营人员，我想要在调账明细列表中看到"资源子类"列，以便不进详情就能识别该笔
   调账的细分归属。
6. 作为核算运营人员，我想要切换资源类别或云厂商后，界面能正确处理已选值的联动清空，避免
   提交脏数据。
7. 作为核算运营人员，我只能选择已完成资源子类适配的云厂商，避免进入暂不支持的配置流程。

## 功能需求

### F-001 资源类别枚举扩展

- 新增/编辑调账表单的"资源类别"下拉选项，由 2 项（CPU、GPU）扩展为 4 项：
  **CPU、GPU卡、GPU API、GPU其他**。
- 4 个选项对所有云厂商均展示，不按云厂商过滤选项本身。
- 新增行的资源类别默认值为 **CPU**。

### F-002 资源子类下拉列（新增/编辑表单）

- 表格新增一列"资源子类"，位置紧跟在"资源类别"列之后（"资源类别"列和"金额"列之间）。
- 资源类别 = GPU卡 时，下拉候选为该云厂商的卡型清单。
- 资源类别 = GPU API 时，下拉候选为该云厂商的模型厂商清单。
- 资源类别 = CPU 或 GPU其他 时，下拉无候选项（清单为空），字段留空。
- 该字段**非必填**（不展示必填红星），无有效选择时视为空值。

### F-003 资源子类候选清单按云厂商联动

- 仅当云厂商 ∈ **{aws, gcp, huawei}** 时，才允许请求卡型/模型厂商候选接口；这 3 个厂商之外的
  云厂商（如 azure、zenlayer、tcloud 等）不能请求接口。
- 云厂商不在上述 3 个范围内时，"资源子类"下拉展示为空（无选项），用户无法选择任何值，提交
  时传空字符串。
- "资源类别"下拉本身的 4 个选项**不**按云厂商过滤——所有云厂商都能选"GPU卡"/"GPU API"。
- aws、gcp、huawei 均属于接口支持的云厂商；资源子类候选以接口返回结果为准，不在 PRD 中对任一
  支持厂商预设为空。

### F-004 列表页资源子类列

- 调账明细列表页，"资源类别"列和"调账类型"列之间新增"资源子类"列。
- 直接展示该笔调账的资源子类值；值为空时展示 "--"。
- 本期**不**新增按资源子类的筛选/搜索功能。

### F-005 提交字段规则

- 提交调账明细数据时，"资源子类"字段始终以字符串形式提交，不允许缺失或未定义。
- 当前渲染下"资源子类"没有有效选择（资源类别为 CPU/GPU其他，或云厂商不支持查询）时，
  提交空字符串。
- 渲染后已隐藏/清空的"资源子类"值不能带着切换前的旧值一起提交。

### F-006 资源类别 / 云厂商切换时的联动清空

- 用户切换"资源类别"后，若原"资源子类"的值不属于新类别对应的候选清单，清空该行"资源
  子类"的值。
- 用户切换顶层"云厂商"后（影响所有行），清空所有行的"资源子类"值，因为候选清单随云厂商
  变化。
- 编辑模式下"云厂商"字段不可编辑（沿用现有规则），因此编辑态不会触发"切换云厂商清空"。

### F-007 云厂商选择范围

- 新增/编辑表单顶部的"云厂商"选项中，仅 **aws、gcp、huawei** 保持可用。
- 除上述 3 种已完成资源子类适配的云厂商外，其余云厂商选项统一置为 disabled，不允许用户选择。
- disabled 仅作用于云厂商选择控件，不改变已有数据的展示；编辑已有非适配云厂商数据时，当前值仍需正常展示。
- 资源类别的 4 个选项不因本规则减少；用户在可用云厂商下仍可选择 CPU、GPU卡、GPU API、GPU其他。

| R-001 | 资源类别四值：CPU、GPU卡、GPU API、GPU其他 |

## 验收标准

- **AC-001**：Given 新增调账表单，When 打开"资源类别"下拉，Then 展示 CPU/GPU卡/GPU API/GPU
  其他 四个选项（所有云厂商一致）。
- **AC-002**：Given 云厂商=aws 或 gcp 或 huawei，When 资源类别选择"GPU卡"，Then 请求该厂商的
  卡型接口并按接口返回结果展示候选列表。
- **AC-003**：Given 云厂商=aws 或 gcp 或 huawei，When 资源类别选择"GPU API"，Then 请求该厂商的
  模型厂商接口并按接口返回结果展示候选列表。
- **AC-004**：Given 云厂商=azure（或 zenlayer/tcloud 等非白名单厂商），When 资源类别选择
  "GPU卡"或"GPU API"，Then 资源子类下拉展示为空（无选项）。
- **AC-005**：Given 资源类别=CPU 或 GPU其他，When 查看资源子类下拉，Then 展示为空（无
  选项）。
- **AC-006**：Given 已选择资源类别=GPU卡且已选中某个卡型，When 将资源类别切换为 CPU，
  Then 资源子类的值被清空。
- **AC-007**：Given 已选择资源类别=GPU卡且已选中某个卡型，When 将顶层云厂商从 aws 切换为
  gcp，Then 该行资源子类的值被清空。
- **AC-008**：Given 已填写完整的一行调账数据，When 点击提交，Then 请求体中资源子类字段
  始终为字符串（选中值或空字符串），不会是 undefined 或缺失该字段。
- **AC-009**：Given 调账明细列表数据中某条记录资源子类有值，When 查看列表，Then "资源
  类别"列后紧跟"资源子类"列，展示该值。
- **AC-010**：Given 调账明细列表数据中某条记录资源子类为空，When 查看列表，Then "资源
  子类"列展示 "--"。
- **AC-011**：Given 打开新增或编辑调账表单，When 查看"云厂商"选项，Then aws、gcp、huawei
  可选择，其余云厂商选项显示 disabled 且不可选择；已有非适配云厂商记录进入编辑态时，当前值仍
  正常展示。
