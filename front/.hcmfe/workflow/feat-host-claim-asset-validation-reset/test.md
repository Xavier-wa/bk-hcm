> 本轮增量: 普通模式同步支持固资号自动校验；沿用 300ms 防抖与竞态保护

## 验证范围

- 功能边界: 滚服推荐模式与普通模式下，用户手动修改固资号后立即失效旧校验状态，停止输入 300ms 后仅校验最新值，并阻止过期响应覆盖新结果。
- 回归边界: 滚服推荐值仍立即校验；手动点击校验仍立即执行，并取消尚未发出的防抖请求。
- 不在范围: 固资号校验接口业务规则、机型推荐规则。

| ID | 场景 | 前置 | 操作 | 期望 | covered-by | 回滚 |
|----|------|------|------|------|------------|------|

| P0-02 | 拦截普通模式过期响应 | 普通模式下首个请求响应较慢 | 输入值 A 触发请求后立刻改为 B，并让 A 晚于 B 返回 | 最终只展示 B 的校验结果；A 的响应不得覆盖 B，也不得提前结束 B 的校验中状态 | | 恢复接口延迟 |
| P0-03 | 未校验最新值不可确认 | 普通模式下已有一次成功校验结果 | 修改任意一个字符后立即点击确认，并分别观察等待中、失败、成功状态 | 修改后确认立即禁用；等待中和失败时不可确认；最新值成功后才恢复 | | 恢复有效固资号 |
| P0-04 | 手动校验取消待发防抖 | 普通模式下输入后尚未满 300ms | 立即点击手动校验按钮 | 立即发送一次当前值校验请求；原定防抖请求被取消，后续不重复发送 | | 清空输入 |
| P0-05 | 清空固资号不发请求 | 普通模式下已校验成功 | 清空输入框并等待超过 300ms | 旧结果立即清除，不发送空值校验请求，确认保持禁用 | | 恢复有效固资号 |
