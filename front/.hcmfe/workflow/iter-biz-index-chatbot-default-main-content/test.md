## 验证范围

- 功能边界: 业务视角首页 chatbot **默认主内容区（首页空态）**——欢迎区（云朵图标 + 欢迎语 + 功能 tips）、响应式**大卡片**（点击直发）、输入框上方**小卡片排**（点击注入「场景 tag + 默认词」待发送 + 单按钮分段翻页）、空态收敛、带 `session_tag` 会话归类。
- 稿面对齐: 全局面包屑替代会话标题、底部「有任何问题可联系 @小助手」（w-name）、主内容区灰底/间距/左右留白响应式、小卡片排与输入框同宽、场景 chip 两列布局 + 进入带 tag 会话只读回显。
- 接口: 无新增后端接口；场景标识通过 `create_session` 的 `session_tag` 入参透传（后端已就绪），前端仅 `host_apply → 主机申领` 名称映射。
- 不在范围:
  - 侧边栏会话列表 CRUD / 搜索 / 置顶 / 文件夹（上一迭代 `iter-biz-index-chatbot-session-sidebar`）
  - 对话流 SSE / 消息区 / HITL / 流式交互
  - 路由、顶栏、左侧业务菜单、全局布局
  - 快捷卡片的后台配置管理（前端固定配置，无接口）
  - `host_apply` 之外场景的 `session_tag`（暂未配置，落入未分组）

## 测试环境

- 前端入口: `<对应业务的测试环境地址，由执行人在测试时确认；URL 形如 /business/chatbot 且带 ?bizs=<bizId>>`
- 测试账号: `<test_account>`（需具备 `biz_agent_assistant` 业务智能体助手权限）
- 数据准备:
  - 在目标业务（有效 `bizs`）下，确保可进入 chatbot 首页空态（未选中会话、无消息）。
  - 用于验证只读回显：准备/创建至少 1 个带 `session_tag=host_apply` 的会话（可通过点击「主机申领」大卡片或小卡片发送后产生），再从侧栏切回该会话。
  - 响应式验证：准备宽屏（≥1440px）与窄屏（≈768px / 拖拽缩窄浏览器）两种窗口宽度。
  - 接口失败分支：用浏览器 DevTools 把 `sessions/create` 请求 mock 成 500 / 断网，验证失败反馈（实现为 `console.error` 静默降级，不抛全局错误、不产生脏会话）。

## 备注（设计/编码差异，便于测试判读，非缺陷）

1. **底部联系人文案**：design §2.5 稿面写「@小鲸手」，实现按用户最新要求为「**@小助手**」，用 `w-name` 组件渲染。
2. **w-name 企微账号待确认**：`ASSISTANT_CONTACT.name` 暂用占位「小助手」（见 `constants.ts` TODO）。点击拉起的企微账号需产品确认真实 ID 后替换，测试时若拉起的不是目标联系人属已知占位项，非缺陷。
3. **背景色取值**：design 未给精确色值，实现取蓝鲸常规页面灰 `#f5f7fa`。若产品有精确稿面色值需回 coding 调整。
4. **小卡片翻页语义**：单按钮——前进到末段后单击回到首段（多于 2 段时也可逐段前进、末段一键回首），契合稿面「再次点击回到之前」。
5. **场景 chip 实现**：chat-x `ChatInput` 的 v-model 无法注入富文本 tag 节点，故场景 chip 由 `#input-header` 插槽自绘 + 绝对定位左列 + 编辑器 `padding-left` 让出右列实现两列布局（依赖内部类名 `.ai-slash-input`，组件升级需复核）。
6. **接口失败反馈**：create 失败为 `console.error` 静默降级、无 Toast。若需可感知失败提示属增强项，记入后续迭代。
