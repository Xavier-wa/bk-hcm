## 一、需求背景与目标

### 1.1 背景

**现网操作路径**：资源管理 - 购买主机 - 选择「滚服项目」- 配置清单「+添加」- 增加资源需求（选择云地域）- 添加机型配置（弹框）。

**滚服的业务本质**：用一台即将退回的旧设备的剩余计费周期，去申领新机型——即"以旧换新、继承套餐"。滚服申领由平台侧管理员按照约定的额度统一提交预测，用户无需参与预测提报。

**痛点**：

- 固资号为纯文本输入，用户必须**自行查找**符合条件的固资号后粘贴进来，再点击"手动校验"；
- 对于**场景1用户**（本质只想快速申请新设备、走滚服免预测），寻找合适固资号的过程繁琐且门槛高；
- 输入错误的固资号校验失败后，缺少引导。

### 1.2 目标

1. **场景1（简化申请）**：用户可以**无需手动输入固资号**，系统根据已选地域+机型自动推荐最优继承固资；
2. **场景2（真滚服替换）**：用户仍可手动输入指定固资号，不影响现有使用方式；
3. 两种场景在同一页面共存，通过简洁的交互切换。

## 二、用户故事

### 场景1：简化申请（自动推荐固资）

- **用户画像**：想申请新设备，利用滚服项目免去提交预测的流程
- **用户已知**：需求的**地域**和**机型**（或机型族）
- **期望体验**：选好地域和机型后，系统自动匹配并填入固资号，无需手动查找
- **系统职责**：根据已选「地域 + 机型族 + 当前业务（页面选择入口所选业务）」，按校验规则筛出候选固资，标记已使用时长 ≥ 36 个月的为推荐，自动回填（有标准型优先标准型，否则取第一个）

### 场景2：真滚服替换（手动指定固资）

- **用户画像**：业务下确有待退回设备，要用该设备申请新机型
- **用户已知**：明确要继承的**固资号**
- **期望体验**：与当前流程一致——输入固资号 - 校验 - 继承套餐
- **系统职责**：以用户输入的固资号执行完整校验

## 三、需求点清单

### R-1 固资号区域改造为「下拉选择器 + 手动输入」双模式

- 固资号字段由「纯文本输入 + 手动校验按钮」改造为**下拉选择器**；
- 下拉框 placeholder：**「选择继承机器的固资号」**；
- 右侧保留**「手动校验」按钮**；
- 下拉面板展开后提供：机型族 Tab、候选固资列表（详见 R-2 / R-4）。
- **选择固资后自动调用「手动校验」**（父需求评论区 dommyzhang 2026-08-05 确认）。

### R-2 机型族 Tab 分类

- 下拉面板内按机型族分类展示：标准型 / 高IO型 / 大数据型 / 计算型 / GPU型（**无"全部"Tab**）；
- 每个 Tab 后标注该族候选固资数量（如「标准型 103」）；
- **候选数量为 0 的 Tab 直接隐藏**；
- **如果对应 Tab 没有设备，展示文案「该机型族没有符合要求的CVM实例」**（父需求评论区 dommyzhang 2026-08-05 确认）；
- 切换机型族 Tab 联动候选列表与推荐逻辑（见 R-5 / R-7）。

### R-3 ~~搜索框~~（已去掉）

> **父需求评论区 dommyzhang 2026-08-05 确认**：去掉下拉搜索框（候选数量少，只有 5 个左右），不需要搜索功能。

### R-4 候选固资列表展示

每行展示以下字段：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 固资号 | 固资编号 | TC260320003234 |
| IP | 设备 IP 地址 | 9.136.163.19 |
| 机型 | 固资对应的机型规格 | IT5.MEDIUM8 |
| 计费模式（剩余时长） | 计费模式 + 括号标注剩余月数 | 包年包月(剩余8月) |
| 开始时间 | 计费开始时间 | 2024-06-10 |
| 结束时间 | 计费结束时间 | 2027-06-10 |
| 推荐标记 | 系统推荐固资标记「推荐」badge（橙色） | [推荐] |

**排序规则**：推荐项（已使用时长 ≥ 36 个月）置顶，其余按已使用时间降序排列。

### R-5 推荐逻辑

**触发条件**：

- 只要有可用区被选中（含默认选中），**立即触发**推荐；
- 切换可用区时重新触发；
- 切换机型族 Tab 时重新触发。

**推荐算法**：

1. 以「地域 + 机型族 Tab + 当前业务（页面选择入口所选）」为输入；
2. 按六条校验规则筛选候选固资集；
3. 下拉列表后端返回一个大列表，由**前端分组**，排序前端确定；
4. 按**已使用时间**降序排序；
5. **推荐标记规则**：已使用时长 **≥ 36 个月**的固资标记为「推荐」badge（橙色）置顶（后端加上相关信息）（父需求评论区 dommyzhang 2026-07-23 确认，替代原 TOP5 方案）；
6. **自动回填策略**：取第一个分组的第一个数据回填——**有标准型就用标准型，没有标准型就取第一个数据回填**（父需求评论区 dommyzhang 2026-07-23 确认）；
7. 回填后**自动调用「手动校验」**（父需求评论区 dommyzhang 2026-08-05 确认）。

**联动行为**：

- 选择固资后自动锁定计费模式和购买时长；
- 切换可用区 → 重新推荐，**覆盖之前选择**；
- **可用区选到「全部」时，取消固资号回填**（可用区选择器有"全部"选项，与固资号下拉 Tab 栏是两个独立业务功能）；
- 切换机型族 Tab → 重新推荐，**覆盖之前选择**。

### R-6 手动输入模式

- 在选择框中直接输入固资号 + 点击「手动校验」；
- 校验通过则锁定，失败则提示具体原因。

### R-7 完整校验逻辑（六条规则）

所有继承固资（无论自动推荐还是手动输入）必须**同时满足**以下六条：

| # | 校验项 | 规则 |
| --- | --- | --- |
| 1 | 归属运维部门 | DeptName == IEGDeptName（必须属于 IEG） |
| 2 | 归属业务 | 必须等于**页面选择入口中用户所选的业务** |
| 3 | 计费信息完整 | 计费模式非空、有计费开始时间；包年包月还需有计费结束时间 |
| 4 | 设备类型 | 必须是通用机型（DeviceTypeClass == CommonType） |
| 5 | 实例地域 | 固资实例地域必须与所选城市/地域一致 |
| 6 | 机型族与计费匹配 | 最终匹配的可用机型与继承固资的**机型族一致、计费模式一致** |

**继承规则**（校验通过后）：

- 计费模式 = 继承固资的计费模式（锁定，不可改）；
- 购买时长 = 剩余时长（锁定，不可改）；
- 计费开始时间 = 继承固资的计费开始时间；
- 计费结束时间 = 申请时间 + 剩余时长；
- 可选机型范围限定为该固资的**机型族**；
- 选中后展示「已继承固资套餐」信息。

### R-8 多台申领与并发

- 每个「添加机型配置」弹框中**独立选择固资号**（沿用 1:N 关系）；
- 同一固资号**允许被多人同时选中并提交**（不做互斥）。
