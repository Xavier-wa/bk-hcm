## 背景与目标

当前「修改预测」强制「调整配置 / 调整时间」二选一，同一业务诉求（例如延期到货同时改台数）需拆成两张调整单、重复审批。本期前端实现目标：同一张调整单可同时改时间与数量，并覆盖调整内新增、预测专用日历、废弃「部分延期」等配套体验。

## 用户故事

1. 作为 **资源预测提单人**，我想在「修改预测」时同一张需求同时调整期望到货时间与机型/数量，以便一个业务诉求只需开一张调整单。
2. 作为 **资源预测提单人**，我想在调整预测流程内也能新增一条预测，以便调整与新增一次完成。
3. 作为 **资源预测提单人**，我想用预测专用日历选择期望到货时间，以便获得周相对关系、预测内外、可申领区间等场景反馈。
4. 作为 **审批人**，我想在一张调整单中清楚看到「时间变更」与「数量变更」两类明细，以便准确判断预算等影响。
5. 作为 **提单人/管理员**，我希望原「部分延期」入口下线并有迁移引导，以免走已废弃路径。

## 功能需求点

### F-001 同单同时调整时间与数量（P0）

- 取消「调整配置 / 调整时间」互斥二选一；时间与机型/数量同屏可编辑。
- 允许只改时间、只改数量、或两者同时改。
- 提交时按实际变更字段识别语义；一张调整单可同时携带时间变更与数量变更并走审批，无需因组合调整拆单。

### F-002 调整流程内新增预测（P1）

- 「调整预测」流程内支持新增一条预测。
- 新增与修改可混编于同一调整单提交。

### F-003 预测专用日历（P1）

- 新增 / 修改 / 调整等场景的期望到货时间，改用预测专用日历组件。
- 能力需覆盖：周选择、相对周快捷、预测内外提示、可申领区间 / 截止申领等场景反馈（以最终交互稿为准）。

### F-004 废弃「部分延期」（P1）

- 下线唯一入口：资源管理 → 资源预测 → CVM预测（操作菜单中的「部分延期」）。
- 入口移除后给出迁移引导：说明时间 + 数量可在同一调整单完成。

### F-005 调整单 `demand_class` 一致性（P0，增量）

- 预测列表进入调整时，**禁止跨 `demand_class` 混选**（如 CVM 与 CA 不可同批进入调整）。
- 混编（历史行 + 新增行）：新增行**继承**历史行的 `demand_class`；历史行字段原样回填、原样参与提交顶层 `demand_class`。
- 纯新增（表格仅新增行 / 提交 `adjusts` 全为 `add`）：页面提供 `demand_class`（预测用途）选择；整批必须一致；提交时顶层必传。

## 业务规则

| 编号 | 规则 |
| --- | --- |
| R-001 | 取消调整方式二选一；时间/数量可同时编辑、可只改其一。 |
| R-002 | 提交前向提单人展示字段级变更摘要（时间 / 数量 / 机型等改了什么）。 |
| R-003 | 组合调整中的「数量变更」等同常规修改语义，可能触发预算追加。 |
| R-004 | 仅改时间 ≡ 原「延期」；仅改数量 ≡ 原「常规修改」。 |
| R-005 | 审批侧：一张单合并展示，并标注时间变更与数量变更两类明细。 |
| R-006 | 本期仅覆盖**非跨年**组合调整；跨年维持现有「调减 + 调增」行为不变。 |
| R-007 | 纯延期、纯修改单据的审批与预算行为回归不变；权限沿用现有体系。 |
| R-008 | 一次调整入口 / 一张调整单内 `demand_class` 必须唯一；列表侧防混选，纯新增侧可选手选。 |
| R-009 | 历史明细已有 `demand_class`，加载后原样保留；混编新增继承该值；纯新增由用户选择且整批一致。 |

## 输入 / 输出

| 场景 | 输入 | 输出 |
| --- | --- | --- |
| 组合调整 | 同一预测上编辑到货时间与/或机型数量后提交 | 一张调整单同时携带对应变更，进入审批 |
| 仅改时间 | 只改期望到货时间 | 行为等同原延期，不触发数量相关逻辑 |
| 仅改数量 | 只改机型/数量 | 行为等同原常规修改 |
| 调整内新增 | 在调整清单中新增预测行并提交 | 新增与修改同属一张调整单 |
| 废弃入口 | 访问原「部分延期」入口 | 入口不可见，并有迁移引导 |

## 边界与范围

### 本期包含

- 同单同时改时间 + 数量
- 调整时新增预测
- 预测专用日历（体验优化）
- 废弃「部分延期」单入口 + 迁移引导

### 本期不包含

- 主机三池架构相关能力
- 跨年组合调整（维持现有调减 + 调增）

## 验收标准

- **AC-001**：同单同时改到货时间与数量并提交 → 系统接受一张单同时携带时间 + 数量变更，不再要求拆单。
- **AC-002**：只改时间提交 → 行为等同原延期，不触发数量相关逻辑。
- **AC-003**：只改数量提交 → 行为等同原常规修改。
- **AC-004**：提交前展示字段级变更摘要（如时间 X→Y；数量 A→B）。
- **AC-005**：调整单内新增预测并提交 → 新增与修改在同一调整单内完成。
- **AC-006**：原「部分延期」入口下线后不可见，并给出迁移引导。
- **AC-007**：纯延期 / 纯修改单据的审批与预算行为回归不变。
- **AC-S01**：组合调整权限与原调整流程一致，无越权。
- **AC-008**：列表勾选不同 `demand_class` 时无法进入批量调整（禁用或拦截提示）。
- **AC-009**：混编场景新增行 `demand_class` 与历史行一致，提交顶层 `demand_class` 与历史一致。
- **AC-010**：纯新增必须选择 `demand_class` 后才能提交；未选时拦截。
