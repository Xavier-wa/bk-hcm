# PRD - 机房裁撤总览-业务名称未知数据支持显示及明细跳转

## 需求概述

在机房裁撤模块的"裁撤总览"页面中，当后端返回的 `bk_biz_id` 无法在前端全局业务列表中匹配到对应业务名称时，需将业务名称显示为"未知"，并支持点击跳转到裁撤明细页面查看设备明细。同时在搜索栏的"业务名称"下拉中增加"未知"选项，允许用户筛选这些无法匹配的数据行。

## 用户故事

### US-001：查看未知业务数据行

**作为** 运维管理员
**我想要** 在裁撤总览中看到所有数据行（即使业务名称无法匹配）
**以便于** 了解裁撤整体情况

### US-002：跳转查看未知业务明细

**作为** 运维管理员
**我想要** 能够点击"未知"业务名称的行跳转到裁撤明细页面
**以便于** 查看该业务下所有待裁撤设备的明细信息

### US-003：筛选未知业务数据

**作为** 运维管理员
**我想要** 在搜索栏的"业务名称"下拉中选择"未知"选项
**以便于** 筛选出那些业务名称无法匹配的数据行

## 验收标准

### AC-001：未知业务名称显示

- **Given** 裁撤总览页面已加载且存在业务名称无法匹配的行
- **When** 用户查看表格
- **Then** 该行业务名称列显示为"未知"

### AC-002：未知业务行可点击跳转

- **Given** 裁撤总览页面中存在"未知"业务行
- **When** 用户点击该行业务名称按钮
- **Then** 成功跳转到裁撤明细页面并展示该业务的设备明细

### AC-003：搜索栏包含"未知"选项

- **Given** 用户在裁撤总览搜索栏
- **When** 用户打开"业务名称"下拉
- **Then** 列表中包含"未知"选项（值为 0）

### AC-004：筛选未知业务数据

- **Given** 用户在搜索栏选择"未知"选项
- **When** 点击查询
- **Then** 裁撤总览表格只展示业务名称无法匹配的数据行

### AC-005：多选未知和已知业务

- **Given** 用户在搜索栏同时选择"未知"和已知业务
- **When** 点击查询
- **Then** 表格展示两者的合并数据

### AC-006：汇总行不受影响

- **Given** 裁撤总览表格中的汇总行（bk_biz_id=-1）
- **When** 用户查看
- **Then** 汇总行仍显示"汇总"且不可点击跳转

### AC-007：跳转时传 bk_biz_id=0

- **Given** 从裁撤总览点击"未知"业务跳转
- **When** 裁撤明细页面加载
- **Then** URL query 中 `bk_biz_ids` 参数值为 `[0]`

### AC-008：裁撤明细支持 bk_biz_id=0 查询

- **Given** 裁撤明细页面收到 `bk_biz_ids=[0]`
- **When** 查询设备明细
- **Then** 后端返回"未知"业务下的设备明细数据

### AC-P01：性能无影响

- **Given** 业务名称匹配逻辑
- **When** 页面渲染
- **Then** 匹配逻辑在客户端完成，不增加额外网络请求

## 业务规则

1. `bk_biz_id` 无法在 `businessFullList` 中匹配到业务名称时，该行视为"未知"业务
2. "未知"业务在所有接口交互中统一使用 `bk_biz_id=0` 标识
3. 汇总行（`bk_biz_id === -1`）不属于"未知"业务，保持原有"汇总"显示和不可点击行为
4. "未知"业务可以和其他已知业务同时被选中（多选）进行筛选

## 边界范围

### 包含

- 裁撤总览表格"业务名称"列对未知业务的显示处理
- 裁撤总览表格"业务名称"按钮对未知业务的可点击支持
- 裁撤总览搜索栏"业务名称"下拉增加"未知"选项
- 从裁撤总览跳转到裁撤明细时传递 `bk_biz_id=0` 的逻辑
- 裁撤明细页面接收 `bk_biz_ids=[0]` 的查询支持

### 不包含

- 后端接口对 `bk_biz_id=0` 的查询逻辑实现（由后端负责）
- 其他模块（如主机回收）的同类处理
