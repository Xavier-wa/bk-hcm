# PRD：aiagent-同会话内动态切换场景标签

> 工作流：`feat-session-tag-switch`  
> TAPD：`https://<TAPD_HOST>/tapd_fe/69995598/story/detail/1069995598136844127`  
> Requirement：`req-aiagent-biz-index-chatbot`  
> 澄清文档：`docs/reqs/场景标签切换.md`

## 1. 背景与目标

海垒 AI 助手支持多场景会话（如「主机申领」「资源查询」）。创建会话时会打上场景标签；全屏 chatbot 左侧按标签分文件夹，聊天区以只读标签回显当前场景。

Agent 可能在同一次对话中跨场景调度。后端通过 SSE 下发场景切换指令后，若界面标签不更新，用户会误判当前业务语境，左侧列表分组也会错位。

**目标**：收到后端场景切换指令后，同步更新当前会话的场景标签——全屏聊天区标签与左侧会话列表标签（含文件夹归属）一致；浮窗同步会话数据但不新增外显标签。

## 2. 用户故事

作为使用 AI 助手跨场景办事的业务用户，  
我想要在后端通知场景切换后，当前会话的聊天区标签与左侧列表标签同步变为新场景，  
以便于始终按真实业务语境理解与管理会话。

## 4. 功能需求

| 编号 | 需求点 | 优先级 |
|------|--------|--------|
| F-001 | 当前会话流式过程中收到场景切换指令后，按新场景标识更新该会话场景标签；缺少新场景标识则忽略 | P0 |
| F-002 | 全屏：聊天区场景标签（输入区只读 chip）同步为新场景展示名；未知标识回退显示原始值 | P0 |
| F-003 | 全屏：左侧会话列表同步该会话标签，并移动到对应场景文件夹 | P0 |
| F-004 | 浮窗：同步更新会话场景数据；不新增外显场景标签 | P0 |
| F-005 | 同会话可多次切换，以最后一次为准；不强制校验切换前标识是否与当前一致 | P0 |
| F-006 | 若指令对应会话非当前打开会话、但本地列表中存在：更新其标签/分组，不强制切换当前会话 | P1 |
| F-007 | 场景切换处理不得打断正在进行的文本/卡片流式展示；界面应及时反映新标签 | P0 |

## 5. 业务规则

- 新场景标识为准；切换前标识仅作参考。
- 全屏聊天区标签与左侧文件夹归属必须基于同一会话场景标签。
- 假设服务端已持久化新场景标签，刷新后列表应返回新值（联调验证；失败则记后端缺口）。

## 6. 后端指令约定（产品视角）

后端在对话流中下发自定义指令，名称表示「场景已切换」，载荷包含切换前/后场景标识。示例语义：`host_apply` → `resource_query`（展示为「主机申领」→「资源查询」）。

本期仅要求在**当前会话流式过程中**响应该指令；历史回放暂不要求。

## 7. 验收标准

| ID | Given | When | Then |
|----|-------|------|------|
| AC-001 | 全屏打开「主机申领」会话，聊天区标签为「主机申领」 | 流式过程中收到切换到「资源查询」的指令 | 聊天区标签变为「资源查询」；该会话出现在「资源查询」文件夹并离开「主机申领」 |
| AC-002 | 同会话内连续收到多次切换指令 | 最后一次指向某场景 | 聊天区与侧栏均以最后一次为准 |
| AC-003 | 新场景标识无中文映射 | 收到切换指令 | 仍更新标签，展示为原始标识 |
| AC-004 | 浮窗助手正在流式对话 | 收到切换指令 | 会话场景数据已更新；浮窗无新增外显标签 |
| AC-005 | 按服务端已持久化假设 | 刷新后重新拉取会话列表 | 该会话场景标签为切换后的值（联调；失败记缺口） |
| AC-006 | 指令缺少新场景标识 | 收到指令 | 忽略；对话与标签保持原状 |
| AC-007 | 正在流式输出文本/卡片 | 同时收到切换指令 | 流式展示不被中断，标签仍更新 |

## 8. 范围

### 本期包含

- 流式过程中的场景切换标签同步（全屏 chip + 侧栏文件夹；浮窗数据侧）

### 本期不包含

- 历史回放中的场景切换处理（暂定）
- 浮窗新增外显场景标签
- 场景映射表的运营配置化
- 强制校验切换前标识必须等于当前标签
- 后端持久化实现（若缺失，另开后端配合）
