# Design：Chatbot HITL 中断交互 — 业务选择列表

## 1. 设计目标

将 Agent 下发的 `hitl.interrupt` 消息从纯文本渲染升级为交互式选择卡片，降低用户认知成本，提升对话流畅度。

## 2. 整体布局

选择卡片作为 AI 消息的一部分，嵌入在消息气泡内，整体布局如下：

```
┌─────────────────────────────────────────────┐
│  🤖 AI 助手                                  │
│                                             │
│  请选择要查询预测的业务：                      │
│                                             │
│  ┌─────────────────────────────────────┐   │
│  │  ○ reborn (ID: 213)                 │   │
│  │  ○ 蓝鲸 (ID: 2005000002)            │   │
│  │  ○ cc3.0测试 (ID: 100605)           │   │
│  │  ○ Gsekit测试专用业务 (ID: 2005000002)│   │
│  │  ○ 测试同学专用业务 (ID: 2005000006) │   │
```

## 3. 视觉结构

### 3.1 问题文案区

- **位置**：卡片顶部
- **样式**：14px，常规字重，颜色 `#313238`
- **内容**：`value.question`

### 3.2 选项列表区

- **组件**：`bk-radio-group` + `bk-radio`
- **布局**：垂直排列，每项一行
- **样式**：
  - 选项卡片：圆角 4px，内边距 8px 12px
  - 默认状态：背景 `#f5f7fa`，边框 1px solid `#dcdee5`
  - 悬停状态：背景 `#e1ecff`，边框 `#3a84ff`
  - 选中状态：背景 `#e1ecff`，边框 `#3a84ff`，左侧 2px 蓝色指示条
  - 文字：13px，颜色 `#63656e`
- **交互**：单选，点击即选中

### 3.3 自定义输入区

- **位置**：选项列表下方，间距 12px
- **标签**："其他业务："，13px，颜色 `#979ba5`
- **输入框**：`bk-input`
  - 占位文案："请输入自定义业务名称或ID..."
  - 宽度：与选项列表等宽
  - 当用户选择选项时，输入框自动清空；当用户输入内容时，选项列表自动取消选中

### 3.4 确认按钮区

- **位置**：卡片底部，右对齐
- **组件**：`bk-button`，theme="primary"
- **状态**：
  - 未选择且未输入时：disabled 状态
  - 已选择或已输入时：可点击
- **交互**：点击后将选择结果或输入内容作为用户消息发送

## 4. 状态流转

```
┌─────────────┐
│   初始态    │
│  未选择    │
│  未输入    │
│ 按钮置灰   │
└──────┬──────┘
       │
       ├─────────────────┬─────────────────┐
       │                 │                 │
       ▼                 ▼                 ▼
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  点击选项   │  │  输入内容   │  │  切换选择   │
│  选中该项   │  │  清空选项   │  │  取消输入   │
│  清空输入   │  │  按钮可用   │  │  按钮可用   │
│  按钮可用   │  │             │  │             │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                 │                 │
       └─────────────────┴─────────────────┘
                         │
                         ▼
                  ┌─────────────┐
                  │  点击确认   │
                  │  发送消息   │
                  │  卡片只读   │
                  └─────────────┘
```

### 4.1 状态说明

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| 初始态 | 选项未选中，输入框为空，确认按钮 disabled | 卡片首次渲染 |
| 选项选中态 | 某选项被选中，输入框清空，确认按钮可用 | 用户点击选项 |
| 输入态 | 输入框有内容，选项取消选中，确认按钮可用 | 用户在输入框输入 |
| 已确认态 | 确认按钮已点击，卡片变为只读展示，不再响应交互 | 用户点击确认 |

### 4.2 互斥逻辑

- 选项选择与自定义输入互斥：选择选项时清空输入框，输入内容时取消选项选中。
- 已确认的卡片不可再次交互，仅展示用户的选择结果。

## 5. 交互细节

### 5.1 选项选择

- 点击选项卡片即选中，单选模式。
- 选中项有视觉高亮（蓝色边框 + 左侧指示条）。
- 选中后输入框自动清空（如有内容）。

### 5.2 自定义输入

- 输入框获得焦点时，若已有选中项，自动取消选中。
- 输入框支持任意文本输入。
- 输入框失焦不影响状态。

### 5.3 确认发送

- 点击确认按钮后：
  1. 将选择结果（选项文本或输入内容）作为用户消息发送。
  2. 卡片进入只读态，展示用户的选择结果（如"已选择：蓝鲸 (ID: 2005000002)"）。
  3. 等待 AI 后续响应。

### 5.4 异常处理

- 若消息格式不符合预期（缺少 `question` 或 `options`），降级为默认文本渲染。
- 若 `options` 为空数组，仅展示输入框和确认按钮。

## 6. 响应式适配

- 选项列表宽度自适应消息气泡宽度。
- 最小宽度 280px，最大宽度与消息气泡等宽（当前为 1000px 居中）。

## 7. 与现有 UI 的融合

- 选择卡片整体作为 AI 消息的一部分，使用与 AI 消息气泡一致的背景色和圆角。
- 选项列表使用 bkui-vue3 的 `bk-radio` 组件，保持与项目其他表单一致的视觉风格。
- 确认按钮使用 `bk-button` primary 样式，与页面其他主按钮一致。
