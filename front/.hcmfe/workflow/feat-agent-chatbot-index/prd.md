# PRD：Chatbot HITL 中断交互 — 业务选择列表渲染

## 1. 需求背景

HCM Chatbot 与后端 Agent 通过 AG-UI 协议通信。当 Agent 需要用户介入确认时，会下发 `type: "CUSTOM"` 的消息，其中 `name: "hitl.interrupt"` 表示需要人工介入（Human-In-The-Loop）。当前 `MessageContainer` 对这类消息按默认文本渲染，用户无法直观地进行选择操作，体验不佳。

## 2. 用户故事

- 作为用户，当 AI 助手询问"请选择要查询预测的业务"时，我希望看到的是一个可点击的选择列表，而不是纯文本，以便快速做出选择。
- 作为用户，如果选项列表中没有我想要的业务，我希望能够输入自定义内容，而不是被限制在固定选项中。
- 作为用户，当我完成选择或输入后，我希望点击确认按钮将我的选择发送给 AI，继续对话流程。

## 3. 功能范围

### 3.1 支持范围

- 识别 AG-UI 消息中 `type: "CUSTOM"` 且 `name: "hitl.interrupt"` 的消息。
- 解析消息的 `value` 字段，提取 `question`（问题文案）和 `options`（选项列表）。
- 将此类消息渲染为交互式选择列表组件，包含：
  - 问题文案展示
  - 选项列表（单选）
  - 自定义输入框（用于输入不在选项中的内容）
  - 确认按钮
- 用户选择或输入后，点击确认将结果作为用户消息发送，继续对话。

### 3.2 不在本次范围

- 其他 `type: "CUSTOM"` 的消息类型（如 `name` 不是 `hitl.interrupt`）。
- 多选、复选等复杂表单交互。
- 选项列表的分页、搜索过滤。

## 4. 验收标准

| 编号 | 验收项 | 优先级 |
|------|--------|--------|
| AC-1 | 当消息为 `type: "CUSTOM"`、`name: "hitl.interrupt"` 时，渲染为选择列表交互组件 | P0 |
| AC-2 | 选择列表展示 `value.question` 作为问题文案 | P0 |
| AC-3 | 选择列表展示 `value.options` 作为可点击的单选选项 | P0 |
| AC-4 | 提供自定义输入框，允许用户输入不在选项列表中的内容 | P0 |
| AC-5 | 提供确认按钮，点击后将选择结果或自定义输入内容作为用户消息发送 | P0 |
| AC-6 | 非 `hitl.interrupt` 的 CUSTOM 消息仍走默认文本渲染 | P0 |
| AC-7 | 选择列表样式与现有聊天界面风格一致 | P1 |
| AC-8 | 未选择/未输入时，确认按钮置灰不可点击 | P1 |

## 5. 消息格式示例

### 5.1 输入消息（后端下发）

```json
{
  "type": "CUSTOM",
  "timestamp": 1778670366490,
  "name": "hitl.interrupt",
  "value": {
    "question": "请选择要查询预测的业务",
    "options": [
      "reborn (ID: 213)",
      "蓝鲸 (ID: 2005000002)",
      "cc3.0测试 (ID: 100605)",
      "Gsekit测试专用业务 (ID: 2005000002)",
      "测试同学专用业务 (ID: 2005000006)"
    ]
  }
}
```

### 5.2 用户确认后发送的消息

用户选择或输入的内容作为普通用户消息发送，继续对话流程。

## 6. 交互流程

```
后端下发 hitl.interrupt 消息
  → 前端识别并渲染选择列表组件
  → 用户点击选项 或 在输入框中输入自定义内容
  → 用户点击"确认"按钮
  → 将选择/输入内容作为用户消息发送
  → 后端接收用户选择，继续 Agent 流程
```
