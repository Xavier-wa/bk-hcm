## 验证范围

本工作流绑定两张 TAPD 单，用例按单据分组（P0-01 ~ P0-13 属单据 1，P0-14 ~ P0-15 属单据 2）。

- **单据 1** [#137818447](https://<TAPD_HOST>/tapd_fe/69995598/story/detail/1069995598137818447) agent 回复交互体验优化（过程区）
  - 同一轮 reasoning + 工具调用收进过程区：流式展开、结束/历史收起、摘要行切换（F-001 ~ F-003、F-006）
  - 工具参数 `tool_intent` 画在对应工具行上方，`/agui` 与 `/history` 两条路径一致（F-005）
  - 同一轮共用浅底卡片；工具行/思考条稿面样式与状态耗时（F-004）
  - 全页 chatbot、浮窗 `ai-assistant`、历史回放同一套（F-007）
  - PRD 之后追加：单条完成即时收起、工具行 `pending` 第四态、用户气泡对齐稿面（含多行换行）、浮窗默认宽 400→500、手写节点补流式贴底
- **单据 2** [#137725247](https://<TAPD_HOST>/tapd_fe/69995598/story/detail/1069995598137725247) 默认澄清交互实现
  - `hitl.interrupt` 无 options（缺字段 / `null` / 空数组）时按默认澄清渲染自由文本输入框，`/history` 同样出框并回显当时输入
- 不在范围:
  - 后端改动（不新增 HTTP，只消费既有 `/agui` 与 `/history`）
  - 独立「展开全部 / 收起」工具栏按钮、稿面级完整入参/出参面板、工具名中文映射表（PRD §8 明确不做）
  - 改 `/history` 消息顺序或要求后端补 `duration`、补 `tool-intent`
  - 点赞/复制、输入框、会话列表本身的功能
  - 单据 2 的实时流解析路径（现状已可用，本次只改 `/history` 侧解析与只读回显，见 coding.md 单据 2「要点」）

**已知偏差（需执行人确认可接受）**：PRD `AC-010` 原文要求工具内部详情「仍是现有组件交互」，实现改为手写三字段详情（描述/参数/返回内容），未复用 chat-x `ToolcallRender` —— 理由是稿面行头/底色/字号与组件不一致（coding.md §一）。`AC-010` 的实质约束「不新做完整入参/出参面板」仍满足，但字面上不再是「现有组件」。用 P2 一条兜底核对，不按 PASS/FAIL 计。

## 测试环境

- 前端入口: `<对应 HCM 测试环境的 chatbot 入口，由执行人在测试时确认；不要把具体域名写入仓库>`
  - **三种形态都要覆盖**：全页 chatbot、浮窗 `ai-assistant`、历史会话回放
- 测试账号: `<test_account>`（需具备 `agent_assistant`；另备一个无该权限的账号验 AC-S01）
- 数据准备:
  - **首选真实链路**：登录后发起主机申领类对话，让 agent 在一轮内产生「多次思考 + 多次工具调用」（典型：`select_account` → `skill_load` → `create_biz_apply`）。这条链路同时能覆盖多 intent 配对、`pending` 态与场景卡贴底。
  - **仅思考轮次**：问一个不触发工具的问题（如纯解释类），用于 AC-005。
  - **停止生成**：在流式中途点「停止生成」，用于 AC-004。
  - **历史回放**：以上每种轮次都要刷新页面 / 重进该会话再看一遍（`/history` 与 `/agui` 是两套消息结构，必须分别验）。
  - **无选项澄清**：需要 agent 下发一条 `hitl.interrupt` 且 `value.options` 为空/缺失的 `human_confirm`。若真实链路不便复现，可按 api.md 的 SSE 样例注入 `CUSTOM` 事件；`/history` 侧需在该轮已回答后重进会话。
  - **浮窗宽度**：验证前请确认浮窗宽度未被本地持久化覆盖（当前实现不持久化，默认值对所有人立即生效）。
