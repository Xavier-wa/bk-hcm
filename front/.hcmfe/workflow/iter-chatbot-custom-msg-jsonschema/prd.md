## 1. 需求背景

当前 chatbot 已支持一种「人工介入选择（HITL）」自定义消息：agent 通过 `CUSTOM` 事件下发 `{ question, options[] }`，前端渲染为一张**选项选择卡片**（单选 + 可选的自定义输入），用户选择后把结果作为一条用户消息回传给 agent 继续流程（见 `hitl-interrupt-card.vue`）。该能力的选项数据结构是**固定写死**的。

本迭代「**自定义消息展示 - jsonschema 模式**」是对上述能力的**泛化**：让 agent 通过一段**简单的 JSON Schema** 来**描述要让用户选择的选项数据**（而非固定结构），前端据此渲染为**选项选择卡片**，用户选择后回传 agent。本质仍是"对话中让用户做选择"，只是选项的描述方式标准化为 JSON Schema、由 agent 灵活下发。

**范围收敛说明（评审结论）**：本迭代**刻意只做"简单选项数据渲染"**，不做复杂的多字段表单、只读信息卡片、需要调接口的业务联动选择器。原因：若完全依赖 agent 下发 JSON Schema 来表达复杂表单 / 卡片，**schema 表达成本**和**前后端耦合的沟通成本**都很高。复杂表单 / 卡片渲染统一放到**指令模板模式**（另一子需求）解决。

**本迭代目标**：① 实现 jsonschema 模式的**基础框架**（agent 下发简单 schema → 前端识别并渲染为选项选择卡片 → 选择回传）；② 在该框架上**落地一个真实场景：云账号选择**（首个接入场景，验证框架可用性）。

## 2. 用户故事

- 作为使用 AI 助手的用户，当 agent 需要我在一组**给定选项**中做选择时（如选一个业务、选一种操作类型），我希望对话里直接出现一张**选项卡片**让我点选，而不是靠我打字描述。
- 作为用户，我选择后希望 agent 能立即拿到我的选择继续后续流程，并且这条选择消息在对话里**留痕**（提交后变只读回显，我能看到自己选了什么）。
- 作为用户，当我回看历史会话时，希望之前的选择消息能**正确回显**当时的选择结果。

## 3. 功能范围

### 3.1 jsonschema 选项选择卡片（本迭代核心，必须）

| 项 | 要求 |
|----|------|
| **定位** | 现有 HITL 选择卡片的**泛化**：选项数据改由 agent 下发的 **JSON Schema** 描述，渲染交互与 HITL 选择类似（Q1 确认）。 |
| **触发来源** | 由后端 agent 在对话流（SSE）中下发一条「jsonschema 自定义消息」事件；前端识别后在对话区**内联渲染**为选项选择卡片（机制对齐现有 HITL 卡片）。 |
| **渲染内容** | 依据 agent 下发的（**简单**）JSON Schema 渲染：可包含提示语 + 一组**选项**。选项的标题/值、可选交互模式等由 schema 描述，前端不写死具体业务选项。 |
| **选项来源** | **纯静态**：选项直接由 schema 给出，**不调接口**拉取（Q5 确认）。需要调接口的业务联动选择器属于指令模板模式，不在本迭代。 |
| **交互形式** | 由 schema 表达的**简单选项交互**，可能为：**单选** / **多选** / **带自定义输入**，具体视该条消息的功能而定（Q4 确认）。本迭代支持这几类简单选项交互，不支持多字段复杂表单。 |
| **提交** | 用户选择后点击「确认/提交」→ 选择结果序列化后，**复用现有发消息通道 `/agui` 作为一条用户消息回传**给 agent，对话继续（机制对齐 HITL 的 `sendMessage`）（Q7 确认）。 |
| **取消** | **不提供**「取消 / 跳过」入口（Q8 确认：仅提交）。 |

### 3.2 提交后状态收敛（本迭代必须）

| 项 | 要求 |
|----|------|
| **提交后只读** | 选择卡片提交后转为**只读回显**态，展示用户已选择的值，不可再次修改/重复提交（对齐 HITL readonly 模式）。 |
| **进行中态** | 提交请求进行中时，确认按钮置 loading / 禁用，避免重复提交。 |

### 3.3 历史回放（本迭代必须）

| 项 | 要求 |
|----|------|
| **历史回显** | 切换/加载历史会话时，jsonschema 选择卡片能正确回显：已提交的展示**只读选择结果**。 |
| **未提交即中断** | 用户未提交就切走/被中断的选择卡片，历史回放时展示为**只读空态**（展示选项但不可操作），对齐 HITL readonly（Q9 确认）。 |

### 3.4 首个落地场景：云账号选择（本迭代必须）

> 来源：用户提供的云账号选择设计稿（PNG）。以下为**产品级行为**，细化视觉/交互在 design 阶段写入 design.md。

| 项 | 要求 |
|----|------|
| **场景** | 进入主机申领模式后，agent 下发"云账号选择"jsonschema 消息，引导用户选择要操作的云账号（**单选**）。 |
| **单账号场景跳过** | 若该场景只有一个云账号，**不展示**该选择步骤，直接进入下一步。 |
| **选择卡片** | 头部提示语（如"已进入主机申领模式。请先选择需要操作的云账号"）+ 一排云账号选项卡，每张含：厂商图标 + 厂商名 + 账号名（如 自研云/ieg-ziyan、腾讯云/test-account、AWS/global-prod）。 |
| **选中收起** | 选中某云账号后，该选择栏**自动收起**，标题 icon 变为**打勾**态，展示一行摘要「您已选择【自研云】- ieg-ziyan」。 |
| **展开回显（只读）** | 点击摘要整行可**展开回显**之前的选择内容；但选中后**不支持交互、无 hover、不允许切换选择**（只读）。 |
| **吸顶回显** | 选择云账号后，**顶部标题栏下方**展示一条选择结果回显，**吸顶展示**（不随对话/页面滚动）。 |

> 说明：云账号数据由 **agent 直接下发**（相对固定，非前端调接口拉取），符合本迭代「静态选项」定位。

## 4. 非目标（不在本迭代范围）

- **复杂多字段表单**渲染（→ 指令模板模式）。
- **只读信息卡片** / 任意自定义渲染内容（→ 指令模板模式）。
- 需要**前端调接口实时拉取选项**的业务联动选择器（→ 指令模板模式）。
  - 注：**云账号选择不属于此类**——云账号是相对固定的数据、当前由 **agent 直接下发选项**，属于本迭代「静态选项」场景。
- **指令模板模式**子需求 `1069995598134649996` 的全部内容。
- chatbot 路由 / 布局 / 侧边栏会话 / 首页空态快捷卡片（前序迭代已完成）。
- agent 后端如何"决定"下发 jsonschema、schema 内容如何生成（后端能力，前端只负责渲染与回传）。

## 5. 验收标准

### P0

- [ ] agent 通过 SSE 下发 jsonschema 选项消息时，对话区内联渲染出选项选择卡片（提示语 + 选项由 schema 驱动）。
- [ ] 选项交互按 schema 表达正确呈现（单选 / 多选 / 带自定义输入按场景），选项为静态、不调接口。
- [ ] 用户选择并提交后，选择结果通过 `/agui` 作为用户消息回传给 agent，对话继续；卡片转为只读回显已选值，不可重复提交。
- [ ] 加载历史会话时，已提交的 jsonschema 选择卡片正确回显只读选择结果。
- [ ] **云账号选择场景**：agent 下发后正确渲染选项卡（厂商图标+厂商名+账号名）；单账号场景跳过该步；选中后自动收起 + 标题打勾 + 摘要行；点击摘要可展开只读回显（不可切换/无 hover）；顶部标题栏下方吸顶回显选择结果。

### P1

- [ ] 提交请求进行中时确认按钮 loading/禁用，避免重复提交。
- [ ] 未提交即被中断的选择卡片，历史回放展示为只读空态，不报错、不白屏。
