# Design：aiagent - 主机申领场景 chatbot · 细节优化（无设计稿）

> **本迭代无独立设计稿**。豁免原因：用户明确「没有新的设计稿」。本迭代为对已上线的主机申领对话卡片的细节优化（展示值编码→名称、修改配置弹窗下拉换真实接口），UI 结构与布局沿用现网卡片，仅改「展示内容」与「下拉数据源」，无新增视觉。

## 0. 本子需求范围

| 在本迭代内 | 不在本迭代内 |
|------------|--------------|
| 卡片 A/B/D 中 8 个编码字段展示为可读名称（含兜底） | 卡片布局 / 样式 / 字段结构变更 |
| 卡片 C「调整配置」弹窗下拉选项复用 CVM 申领页真实接口 | 「添加到配置清单」回填 / 跨页会话联动（上一迭代 QA6） |
| 名称解析失败的兜底展示 | 首页会话归集、申领交互流程功能性变更 |
| C 弹窗下拉的级联 / 加载态（沿用现网交互） | 其它后续追加的细节优化项 |

## 2. UI 参照

- **现网卡片（chatbot 自定义消息）**：
  - 卡片 A 方案推荐 / 卡片 B 预提单 / 卡片 D 确认提交 / 卡片 C 调整配置弹窗 —— 位于 `front/src/components/chatbot/` 下主机申领相关组件（`host-apply-recommend-card.vue`、`host-apply-preorder-card.vue`、`host-apply-submit-card.vue`、`host-apply-adjust-dialog.vue`，以 coding 阶段实际定位为准）。
  - 渲染入口与操作分发：`front/src/components/chatbot/chat-message-list.vue`、`front/src/hooks/chatbot/use-host-apply.ts`。
- **选项数据源参照（CVM 申领页）**：
  - `front/src/views/service/service-apply/hooks/use-cvm-options.ts`（地域 / 可用区 / 机型 / 镜像等选项）
  - `front/src/views/service/service-apply/hooks/use-disk-options.ts`（磁盘类型等选项）
- **PRD 文字约束**：
  - 编码→名称覆盖 A/B/D 卡片只读展示位 + 编辑回显（PRD §F1）。
  - C 弹窗下拉来源与 CVM 申领页口径一致（PRD §F2）。
  - 名称缺失时兜底回退原编码，不出现空白 / 报错（PRD §F1.4 / AC-2）。

## 3. 与 PRD 验收映射

| PRD 验收项 | Design 结论 |
|------------|-------------|
| AC-1 A/B/D 字段展示名称 | 沿用现网卡片版式，仅把字段单元格展示值由编码替换为名称；展示形态（是否「名称(编码)」并存）见 §4 待 api/coding 定 |
| AC-2 名称无法解析兜底 | 沿用现网展示控件，无映射时回退原编码字符串，不改布局 |
| AC-3 C 弹窗下拉为真实接口数据 | C 弹窗沿用现网下拉控件外观，仅将候选数据源由静态枚举切换为 CVM 选项 hook |
| AC-4 下拉级联 | 沿用 CVM 申领页既有级联与加载交互（如地域→可用区→机型），无新交互设计 |
| AC-5 编辑保存后回显名称 | 沿用现网 B 卡回显位置，值同步为名称 |

## 4. 待 api/coding 阶段确认（不阻塞 Design）

1. **名称数据来源**：复用 CVM 选项数据按 value 反查 label，还是后端 SSE 补名称 / 新增字典接口（倾向复用 CVM 选项反查）。

3. **C 弹窗下拉字段与级联范围**：哪些字段换真实接口、是否需要地域→可用区→机型级联、磁盘类型是否走接口。
4. **业务上下文来源**：CVM 选项接口所需业务 id / 云账号等上下文在对话场景下的来源。
