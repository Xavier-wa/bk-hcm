# API — 自研云证书-云上不支持删除，页面需提示

## 0. 结论

**本需求不新增接口、不变更任何接口契约、不新增数据字段。**

判定完全依赖证书列表接口**已返回**的 `vendor` 字段，改动面为纯前端渲染层拦截。删除接口本身保持原样，只是自研云证书在界面上不再可达（按钮置灰，点击不触发请求），因此删除接口实际不会被自研云证书调用。

## 1. 涉及的现网接口

| 接口 | 用途 | 本次是否变更 |
|------|------|--------------|
| 证书列表查询 | 拉取证书列表，响应中每行含 `vendor` 字段 | 否（仅读取其既有字段） |
| 证书删除 | 删除指定证书 | 否（调用方式与参数不变；自研云场景在前端被拦截，不会发起） |

### 1.1 证书列表查询（只读依赖）

- **调用方**：证书管理页面通过 `useTable({ requestOption: { type: 'certs' } })` 发起；按当前视角选择数据源——业务视角走「业务下资源列表」通道，资源视角走「资源下资源列表」通道。
- **请求要点**：分页 + 排序（默认按 `cloud_created_time` 倒序）+ 过滤规则；资源视角下会追加 `bk_biz_id` 规则。
- **本次依赖的响应字段**：

| 字段 | 类型 | 说明 | 用途 |
|------|------|------|------|
| `vendor` | string | 证书所属云厂商枚举值 | **唯一判定来源**。自研云取值为 `tcloud-ziyan`（与列表「云厂商」列展示同源，列定义见 `use-columns.tsx` 的 `certColumns`） |
| `bk_biz_id` | number | 证书分配的业务 ID，`-1` 表示未分配 | 既有「已分配业务」禁用判定的输入，本需求不改其逻辑 |
| `id` | string | 证书 ID | 删除操作入参（自研云场景不再触发） |

- **字段缺失兜底**：`vendor` 缺失时按「非自研云」处理（PRD R-005），保持原有可删除行为，不误伤存量数据。

### 1.2 证书删除（不变）

- **调用方式**：维持现状，由列表操作列「删除」按钮的点击回调触发确认弹窗后调用。
- **本次改动对它的影响**：自研云证书的按钮处于 `disabled` 态，点击不触发回调，因此**不会发起该请求**。接口签名、参数、错误码全部不变。

## 2. 错误码

**不适用。** 本需求在前端入口层拦截，不引入新的失败路径；原先自研云删除必然返回的云上错误（未授权 / 不支持删除）在自研云场景下不再产生，因为请求根本不会发出。

## 3. 前端与接口的边界

```
列表接口响应（含 vendor）
      │
      ├─ vendor === 'tcloud-ziyan'  →  删除按钮 disabled + tips「不支持自研云」→ 不发请求
      │
      └─ 其它 vendor                →  沿用既有判定（权限 / 已分配业务）→ 行为完全不变
```

- 判定发生在**渲染层**，不产生任何额外请求（对应 AC-P01）。
- 服务端不做配合改造，前后端无新增联调项。
