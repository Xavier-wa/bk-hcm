# Design：自研云证书-云上不支持删除，页面需提示（无设计稿）

> **本迭代无独立设计稿**。豁免原因：本需求为**纯渲染层拦截**——仅将证书列表操作列的既有「删除」按钮在自研云场景下置灰，并复用列表已有的 tooltip 机制挂载一条固定文案提示。不新增页面、不新增控件、不新增图标、不改动布局，沿用现网 UI 与交互范式，无需设计师出稿。

## 0. 本子需求范围

| 在本迭代内 | 不在本迭代内 |
|------------|--------------|
| 证书列表操作列「删除」按钮按云厂商（自研云）置灰 | 新增页面 / 弹窗 / 侧栏 / 表单 |
| 置灰按钮的悬停 tips 文案「自研云证书不允许删除，如有疑问，请联系C2000」 | 新增图标、新增按钮、调整操作列布局 |
| 业务视角与资源视角同时生效 | 批量删除入口（产品当前不存在） |
| 与既有「已分配业务」禁用提示的优先级收口 | 删除接口 / 删除确认流程 / 权限模型改动 |

## 2. UI 参照

- **现网**：证书管理列表（业务视角「证书托管」与资源视角「资源管理 - 证书」复用同一页面组件）。参照对象为该列表**操作列已有的禁用态**：
  - 禁用态沿用现网 `Button(text theme='primary' disabled)` 的置灰表现，**不引入新的视觉样式**；
  - 提示气泡沿用现网操作列的 `v-bk-tooltips` 机制（文案挂在按钮外层 `span` 上），**不新增提示载体**。
- **PRD 文字约束**（摘录与界面相关的验收描述）：
  - 「删除」按钮为置灰状态且点击无响应（不弹确认框、不发请求）；
  - 悬停提示气泡文案为「自研云证书不允许删除，如有疑问，请联系C2000」，固定不拼接；
  - 按钮可点击（非自研云且无其它禁用原因）时不展示该提示；
  - 自研云与「已分配业务」同时成立时，提示统一为「自研云证书不允许删除，如有疑问，请联系C2000」；
  - 无删除权限时按钮同样为置灰态，权限禁用行为与之前一致。

## 3. 交互状态定义（操作列「删除」按钮）

按钮的可点击态与提示文案由以下**判定顺序**唯一决定（自上而下命中即止）：

| 优先级 | 判定条件 | 按钮状态 | 悬停 tips | 说明 |
|--------|----------|----------|-----------|------|
| 1 | 当前行证书云厂商为自研云 | 禁用（置灰，点击无响应，不弹确认框、不发请求） | 「自研云证书不允许删除，如有疑问，请联系C2000」 | 本期新增判定；自研云是最根本的不可用原因 |
| 2 | 资源视角 且 该证书已分配业务 | 禁用（置灰） | 「该证书已分配业务, 仅可在业务下操作」 | **现网既有行为，保持不变** |
| 3 | 当前用户无删除权限 | 禁用（置灰） | 无（沿用现网权限禁用表现） | **现网既有行为，保持不变** |
| 4 | 其它（默认） | 可点击 | 无 | 与改动前完全一致 |

**优先级说明（对应 PRD R-003）**：自研云是最前置、最根本的不可用原因。当「自研云」与「已分配业务」同时成立时，走优先级 1，提示统一为「自研云证书不允许删除，如有疑问，请联系C2000」。

**与无权限条件的关系**：现网 tooltip 的启停**只与禁用原因有关，与是否有权限无关**（即无权限 + 已分配业务时，现网同样展示「已分配业务」提示）。为保持同构、把改动面收敛到最小，本期新增的自研云提示沿用同一范式——同样**不随 `noPerm` 变化**。这样 AC-006（无权限时按钮置灰、权限禁用行为与之前一致）依然成立：按钮的禁用态与权限判定逻辑完全不动。

## 4. 与 PRD 验收映射

| PRD 验收项 | Design 结论 |
|------------|-------------|
| AC-001 自研云证书删除按钮置灰且点击无响应 | 沿用现网 `Button disabled` 置灰表现；置灰后不触发 `onClick`，故不弹确认框、不发请求 |
| AC-002 悬停置灰按钮提示「自研云证书不允许删除，如有疑问，请联系C2000」 | 沿用现网 `v-bk-tooltips`，文案固定为「自研云证书不允许删除，如有疑问，请联系C2000」，不做拼接 |
| AC-003 腾讯云证书按钮可点击且不展示该提示 | 非自研云且未分配业务时，按钮可点击且 tooltip 处于 disabled 状态 |
| AC-004 业务视角 / 资源视角均置灰且文案一致 | 判定只看证书自身云厂商，**不引入视角分支**，两视角共用同一段判定 |
| AC-005 自研云 + 已分配业务时提示为「自研云证书不允许删除，如有疑问，请联系C2000」 | 按 §3 优先级表，自研云（优先级 1）覆盖已分配业务（优先级 2） |
| AC-006 无删除权限时按钮置灰、权限禁用行为不变 | 不动权限判定与 `noPerm` 分支；自研云提示同样不随 `noPerm` 变化，与现网「已分配业务」提示同构 |
| AC-007 批量分配业务等其它操作不受影响 | 改动仅落在操作列删除按钮，不触碰 `BatchDistribution` / 上传证书 |
| AC-P01 渲染无额外请求、耗时无变化 | 判定为纯前端字段比对，不新增请求 |
| AC-S01 无权限时点击不可点、不产生删除请求 | 按钮 `disabled`，点击不触发 `onClick` |

## 8. 实现边界纪要

1. **改动面**：仅证书管理列表**操作列删除按钮**的渲染判定与提示文案。不改动删除接口、不改动删除确认流程、不改动权限模型、不改动上传证书与批量分配业务。
2. **判定口径**：以列表行数据自身的云厂商字段为准，与列表「云厂商」列同源；自研云取值 `tcloud-ziyan`。字段缺失按「非自研云」处理（PRD R-005），保持原有可删除行为。
3. **失败兜底**：置灰是**唯一**拦截手段。点击态不可达，因此不存在「点了之后才提示失败」的路径。
4. **不做的拦截**：不在 `handleDeleteCert` 内做二次拦截（按钮已不可达，无需冗余校验）；不做批量删除限制；不做删除前绑定关系校验。
5. **待产品确认（不阻塞实现）**：「无权限 + 自研云」同时成立时，本期按 §3 的「提示与 `noPerm` 无关」范式处理，即展示「自研云证书不允许删除，如有疑问，请联系C2000」。该分支与现网「无权限 + 已分配业务」的处理完全同构，且 AC-006 只约束按钮置灰与权限禁用行为，故按一致性原则落此结论；若产品希望该场景保留权限语义，可在后续迭代单独调整提示优先级。
