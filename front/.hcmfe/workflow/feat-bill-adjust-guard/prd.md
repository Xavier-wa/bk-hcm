# PRD — 账单调整列表状态与守卫

> 来源：TAPD story `1069995598137371364`（拆单时已完成澄清与评估，含后端 Q-005 B；本轮跳过前置节点。评论区为空。）

> 单据：https://<TAPD_HOST>/tapd_fe/69995598/story/detail/1069995598137371364

## 背景

OFS 写入预付费后，会在现网「账单调整」自动生成已确认调账单。运营需要看到每条调账的推送状态和定账状态，并避免误改 OFS 数据；同时，人工录入的已确认调账在非推送中、未定账窗口内应允许修正，而不必删单重建。

本迭代只改现网账单调整列表的状态展示与操作守卫，不改预付费管理菜单/列表/详情/导出，不改手工新增表单，不提供推送状态人工置位入口。

相对 TAPD 原文的产品调整（本轮按最新 list 字段核对）：

- 推送状态**只有四态**：未推送 / 推送中 / 已推送 / 失败。TAPD 草稿里的「超时」不再采用。
- 失败时接口带失败原因；列表不单开列，挂在失败 Tag 的说明上。
- 来源单据 ID（预付费账单 ID）本期**不进列表**，不新开列、不做跳转。

## 用户故事

作为 账单运营
我想要在账单调整列表看到每条调账的推送状态与定账状态
以便于在 OBS 推送异常时定位到具体条目。

作为 账单运营
我想要 OFS 来源的调账在页面上不可编辑不可删除，同时在非推送中且未定账窗口内修正已确认的人工调账
以便于避免破坏 OFS 一致性，并在录错金额时不必删单重建。

## 需求点

1. 账单调整列表新增两列：**推送状态**、**定账状态**。现网「调账状态」（未确认 / 已确认）列保留。
2. 推送状态展示：未推送 / 推送中 / 已推送 / 失败。无「超时」。
3. 定账状态展示：未定账 / 已定账。定账由系统置位，页面无人工入口。
4. 推送失败时，失败 Tag 上可看到失败原因（非失败态无原因）。不单开「失败原因」列。
5. 行操作（编辑、删除）与勾选、批量确认/批量删除，按来源、推送状态、定账状态守卫，不能只加两列而沿用「仅未确认可编辑/删除」。来源为预付费或人工；人工录入无来源单据 ID。

### 操作守卫

| 条件 | 编辑 | 删除 | 勾选 / 批量确认 / 批量删除 |
|------|------|------|---------------------------|
| 来源为预付费（OFS） | 禁用 | 禁用 | 该行不可勾选 |
| 推送中 | 禁用 | 禁用 | 禁用（不可勾选） |
| 已定账 | 禁用 | 禁用 | 批量确认仍按现网「仅未确认」；已定账行不可编辑/删除 |
| 人工来源，且非推送中、未定账 | 允许（含已确认） | 允许 | 仅未确认可勾选参与批量确认；删除按勾选执行 |
| 接口未返回来源（存量行） | 仅未确认可操作 | 同左 | 同现网，**不可**把已确认行放开编辑 |

6. 预付费来源行：操作禁用时给出说明「OFS 预付费调账不可人工修改」。
7. 后端拒绝写操作时，展示接口错误，列表不乐观更新。
8. 人工来源、已确认、已推送、未定账：编辑保存成功后，列表刷新为未确认 + 未推送（以后端结果为准）。
9. 已确认的人工调账不能作为批量确认目标。
10. 增加两列后，当月调账列表查询不应再多打一套无关接口。
11. 接口尚未返回新字段时，两列可为空；操作按「来源缺失」降级，避免误放开。

## 本期不包含

- 预付费管理菜单、列表、详情、导出；来源单据 ID 不在调整列表展示或跳转
- 手工调账新增表单改造
- 审计页面
- 后端守卫与字段落库
- 推送状态人工置位入口
- 「超时」推送态、单独的失败原因列

## 验收标准

- AC-021：调账列表能返回推送/定账字段时，打开账单调整页可见「推送状态」「定账状态」两列（Tag），且「调账状态」列仍在；推送态为未推送/推送中/已推送/失败，无超时。
- AC-021b：推送失败行的失败 Tag 可看到失败原因；非失败态无该说明。
- AC-022：预付费来源行：编辑、删除禁用，无法勾选参与批量确认/批量删除。
- AC-023：人工来源、已确认、已推送、未定账：编辑保存成功后，列表刷新为未确认 + 未推送。
- AC-024：人工来源且处于推送中或已定账：编辑、删除禁用。
- AC-025：已确认的人工调账不可作为批量确认目标。
- AC-026：列表尚未返回来源时，存量已确认行不可编辑（不出现误放开）。
- AC-P04：现网当月调账列表增加两列后查询，无明显额外接口调用。
