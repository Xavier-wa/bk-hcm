# Design：【aiagent-权限点调整】前端鉴权逻辑调整（无设计稿）

> **本迭代无独立设计稿**。豁免原因：纯鉴权逻辑调整，沿用现网菜单显隐、路由无权限去向、通用权限申请页与浮窗入口；无新视觉稿、无新页面形态、无新增图标。

## 0. 本子需求范围

| 在本迭代内 | 不在本迭代内 |
|------------|--------------|
| 首页菜单显隐的能力门改为「平台-智能体助手」 | 新设计菜单 / 新首页视觉 |
| chatbot 页、默认落地页的能力门改为「平台-智能体助手」 | 新做一套申请页交互 |
| 直访无平台权限时复用现网通用权限申请页，申请对象改为「平台-智能体助手」 | 业务会话接口鉴权、IAM 下线旧权限点 |
| 无业务访问时先走现网「申请业务访问」 | 浮窗新形态 / 新申请弹层 |
| 浮窗入口显隐改为「平台-智能体助手」；无权限不渲染 | 旧权限点兼容展示 |

## 2. UI 参照

- **现网业务首页菜单**：`views/chatbot/route-config.ts`（`checkAuth` 控制「首页」入口显隐）
- **现网 chatbot 路由 / 默认落地**：`router/index.ts`、`router/module/business.ts`（无权限去向、落地页能力门）
- **现网通用权限申请页**：`components/permission/apply-dialog.vue`（现网旧申请页即此通用页，直访可进入；本单只改申请对象）
- **现网浮窗入口**：`components/ai-assistant/index.vue`（无权限不渲染）
- **PRD 文字约束**：
  - 有平台权限 + 有业务访问：可见首页菜单与浮窗，可进 chatbot 页（AC-001）
  - 仅有业务访问、无平台权限：无菜单、无浮窗（AC-002）；直访进入通用申请页，申请「平台-智能体助手」，不回退主机页（AC-003）
  - 无业务访问：先申请业务访问（AC-004）
  - 只持有旧权限：无菜单、无浮窗；直访仍申请平台权限（AC-005）
  - 浮窗无权限不渲染、不弹申请（F-004）

## 3. 交互与状态（沿用现网）

| 场景 | 期望表现 |
|------|----------|
| 有平台权限 + 有业务访问 | 菜单「首页」可见；浮窗入口可见；可进入 chatbot 页。页面形态与现网一致 |
| 仅有业务访问、无平台权限（从菜单进入业务） | 无「首页」菜单；无浮窗。无新空态、无新提示条 |
| 仅有业务访问、无平台权限（直访 chatbot 页） | 进入现网通用权限申请页，申请「平台-智能体助手」；不回退主机页 |
| 无业务访问（直访业务视图 / chatbot 页） | 先进入现网业务访问申请；补齐后若仍无平台权限，再进入通用申请页申请平台权限 |
| 只持有旧「业务-智能体助手」 | 与「无平台权限」相同：无菜单、无浮窗；直访申请平台权限 |
| 浮窗无平台权限 | 不渲染浮窗，不弹出申请 |

## 3.y 组件复用（通识）

| 界面块 | 复用层级 | 说明 |
|--------|----------|------|
| 首页菜单显隐 | 现网路由 `checkAuth` | 只改能力门，不改菜单结构 |
| chatbot 页 / 落地 | 现网路由守卫 | 只改能力门与无权限去向的申请对象 |
| 权限申请页 | 现网通用申请页 | 可进入；申请对象改为「平台-智能体助手」 |
| 浮窗入口 | 现网 `ai-assistant` | 只改显隐条件，无 UI 增量 |

## 4. 与 PRD 验收映射

| PRD 验收项 | Design 结论 |
|------------|-------------|
| AC-001 有双权限可见入口 | 沿用现网菜单 / 浮窗 / chatbot 页形态，仅能力门改为平台权限 |
| AC-002 无平台权限无菜单无浮窗 | 沿用现网「无 checkAuth 则不展示」；无新空态 |
| AC-003 直访进通用申请页 | 沿用现网通用申请页；申请对象为「平台-智能体助手」；不回退主机页 |

| AC-005 旧权限不兼容 | 无额外 UI；表现同无平台权限 |
| AC-006 不再读旧权限点 | 无 UI 增量 |
| AC-P01 不新增权限拉取 | 无新请求、无新 loading |
