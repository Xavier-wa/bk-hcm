## 1. 背景与目标

业务首页菜单、chatbot 页、默认业务落地页、智能体浮窗当前检查「业务-智能体助手」。灰度时必须按业务逐个授予智能体权限，成本高。

本单把这些**入口的能力门**改为检查「平台-智能体助手」。用户能否进入某个业务，仍由现有「业务访问」决定。后端会话接口鉴权与 IAM 下线旧权限点不在本单。

**目标**：已授予「平台-智能体助手」的用户，在其已有业务访问的业务里能看到首页与浮窗；未授予平台权限的用户看不到这些入口。直访 chatbot 页时，复用现网通用权限申请页，申请对象改为「平台-智能体助手」。

## 2. 用户故事

- US-1 作为已被授予「平台-智能体助手」的用户，我希望在已有业务访问的业务里看到首页入口和浮窗，以便灰度时不必按业务逐个配置智能体权限。
- US-2 作为只有业务访问、没有平台智能体权限的用户，我希望看不到首页入口和浮窗，以免未灰度到的人误用 agent。
- US-3 作为没有平台智能体权限、但直访了 chatbot 页的用户，我希望进入现网通用权限申请页并申请「平台-智能体助手」，而不是直接回退主机页。现网原先用于业务智能体权限的申请页就是这套通用页，可以进入。
- US-4 作为同时没有业务访问权限的用户，我希望直访时先申请业务访问（沿用现网预期），拿到业务访问后再按 US-3 申请平台智能体权限。

## 3. TAPD 全量解读摘要

来源：tapd-analyst 只读解读（正文无图、评论无图；评论仅有一条「子需求待评审」系统提示，无后续澄清或变更决议）。

- 入口（首页菜单 / chatbot 页 / 默认落地页 / 浮窗）从「业务-智能体助手」改为「平台-智能体助手」。
- TAPD 原文写：无平台权限访问 chatbot 页时回退主机页、不进入旧权限申请页。
- **会话澄清（覆盖原文）**：直访 chatbot 页时提供权限申请页，申请的是「平台-智能体助手」；现网旧申请页是通用页面权限申请页，可以进入，只需把申请对象切到平台权限。若同时没有业务访问，先申请业务访问（现网预期）。
- 不做旧权限兼容；入口显隐不新增一次权限拉取。
- 须与后端子需求同迭代发布，避免入口可见但会话被拒。

## 5. 业务规则（权限矩阵）

| 条件 | 期望 |
|------|------|
| 有平台智能体助手 + 对业务 A 有业务访问 | 进入业务 A 后可见首页菜单与浮窗，可打开 chatbot 页 |
| 仅有业务 A 的业务访问、无平台智能体助手 | 无首页菜单、无浮窗；直访 chatbot 页进入现网通用权限申请页，申请「平台-智能体助手」（不回退主机页；旧申请页可进） |
| 无业务访问（无论是否有平台智能体助手） | 直访业务视图 / chatbot 页时，先申请业务访问（现网预期）；补齐后再按是否有平台权限决定进入页面或展示平台权限申请页 |
| 有平台智能体助手、但对任何业务都无业务访问 | 进不了业务视图，没有入口；直访先申请业务访问 |
| 只持有旧权限「业务-智能体助手」、无平台权限 | 无首页、无浮窗；直访 chatbot 页申请的是「平台-智能体助手」，不是旧权限 |

## 7. 范围

### 本期包含

- 前端：业务首页菜单、chatbot 页、默认业务落地页、智能体浮窗的能力门切换到「平台-智能体助手」
- 直访 chatbot 页时复用现网通用权限申请页，申请对象切换为「平台-智能体助手」；无业务访问时仍先申请业务访问

### 本期不包含

- 业务会话 CRUD 与对话运行接口鉴权（后端子需求）
- IAM 中删除旧权限点「业务-智能体助手」
- 对话运行相关路径（如 `/agui`、`/history`、`/cancel`）的任何调整
- 存量双权限点兼容或授权迁移
- 新做一套申请页交互（沿用现网申请页，只改申请的权限点与先后顺序）

### 依赖

- 可并行开发。端到端灰度弱依赖后端子需求：前端入口改查平台权限后，业务会话须已改为「平台智能体助手 + 业务访问」，否则会出现入口可见但会话被拒。必须同迭代发布。
