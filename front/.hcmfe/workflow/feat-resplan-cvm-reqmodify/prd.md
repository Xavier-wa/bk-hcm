# PRD - 资源预测 2027 CVM 预算提报 · 修改入口 + 截止期限制

- **Requirement**: req-resource-plan-2027-cvm-budget
- **Iteration**: feat-resplan-cvm-reqmodify
- **TAPD**: https://&lt;TAPD_HOST&gt;/tapd_fe/69995598/story/detail/1069995598134389324
- **范围**: 仅前端

## 1. 背景与目标

本迭代覆盖资源预测 (CVM 预算提报) 在 **2027 年度预算提报**场景下两个相互独立但相关的产品需求:

1. **修改单据入口** — 单据被驳回 / 全部失败 / 部分失败 (且无通过子单) 时, 用户可在原单据上修改需求并重新发起, 避免重新创建
2. **非本年预测截止期限制** — 非本年 (currentYear+1 及之后) 的预测有提报截止期, 评审期 (当前日期 > 截止日期, 即截止日期次日起) 内, 业务侧不允许新提交 2027 单据并禁用列表上 2027 行的相关操作; 被驳回的单据仍可通过「修改入口」重新提交 (不受截止期影响)

## 2. 关键概念

| 概念 | 含义 |
|---|---|
| 预算提单截止日期 | 后端 `GET /api/v1/woa/plans/resources/tickets/report_deadline` 返回 `data.deadline` (`YYYY-MM-DD HH:MM:SS`, 精确到秒); **空字符串视为无截止期** |
| 非本年预测起始日 | 前端常量 (本期默认 `'2027-01-01'`), 期望到货日期 **≥ 此日期** 即视为「非本年预测」; **空字符串视为不做区间限制** (与接口空值语义一致) |
| 申报期 | `deadline` 为空 OR 当前时刻 ≤ `deadline`; **不限制非本年预测的提交与操作** |
| 评审期 | `deadline` 非空 AND 当前时刻 > `deadline` (过了截止时刻即生效, 精确到秒); 限制非本年预测的新增提交与列表操作 |

**重要**: 「截止日期」与「非本年起始日」**任一为空**, 即视为不做限制 (兼容后续解除评审期的场景)。

## 3. 功能点

### 3.1 申请单详情页增加「修改需求」入口

- **位置**: `views/ticket/children/resource-plan/detail/index.vue` 详情头部 (`DetailHeader` 区域, 与现有标题/返回同行的操作区)
- **入口形态**: 一个按钮, 文案「修改需求」(默认主题在 design 阶段定)
- **生效范围**: 仅**业务视角** (`isBusinessPage === true`) 展示; 资源预测单据通用 (CVM / CA 均支持, 不在前端按 `demand_class` 过滤)
- **可见性规则** (满足任一即可见, 以后端 MR 3093 「可覆盖状态」对齐):
  - 单据**全部子单驳回** (主单 status = rejected)
  - 单据**全部子单失败 (执行失败)** (主单 status = failed)
  - 单据**部分子单失败/驳回, 且没有任何子单通过** (主单 status = partial_failed / partial_rejected, 子单无 done)
  - 单据**已撤销** (主单 status = revoked) — 与后端可覆盖列表保持一致, 撤销后允许通过修改重提
- **不可见规则** (任一命中即隐藏):
  - 有**任意一个子单已通过** (子单 status = done) — 后端硬规则: 存在 done 子单不允许覆盖
  - 单据**审批中** (主单 status = init / auditing)
  - 单据**已完成** (主单 status = done)
  - 单据**已终止** (主单 status = terminated)
- **特别说明**: 单据没有任何子单 (子单接口返回空数组 / 尚未加载) 时, 均按「无 done 子单」处理, 入口由主单状态白名单决定
- **判断口径**: 前端基于详情接口返回的子单状态自行聚合判定 (无后端「可修改」字段); 具体子单字段映射在 design / api 阶段细化
- **权限**: 不做额外人员限制, 沿用现有体系
- **与截止期的关系**: ⚠ **不受 §3.5 截止期限制影响**, 评审期内仍可见、可点、可提交

### 3.2 修改页

- **触发方式**: 详情页点击「修改需求」, 跳转到**独立的修改页路由**
- **表单结构**: 完全复用新增页 (`views/business/resource-plan/add/`) 的字段与交互, 包括基本信息 / 资源需求列表 / 备注
- **数据回填**: 进入修改页时, 用原单据数据回填全部表单字段
- **页面标题**: 「修改资源预测」(具体文案 design 阶段定)
- **交互行为**: 与新增页一致, **不增加额外二次确认弹窗**
- **提交行为**: 通过 overwrite 新接口提交; 提交成功后**跳回原单据详情页**
- **与截止期的关系**: ⚠ **修改页内的日期选择不应用 §3.5 的日期禁选规则** (与「入口不受限制」语义保持一致)

### 3.3 取消 / 返回

- 修改页提供「取消」入口, 返回到对应单据的详情页 (不丢失原单据状态)
- 浏览器返回行为遵循当前项目 `routerAction` 约定

### 3.4 子单列表「终止」按钮可用状态扩展

- **位置**: 申请单详情页 - 子单列表区域 (`views/ticket/children/resource-plan/sub-ticket/sub-ticket-list.vue`) 标题右侧「终止」按钮
- **变更前**: 仅当主单 `status ∈ { failed, partial_failed }` 时可点击
- **变更后**: 可点击状态扩展为 `status ∈ { failed, partial_failed, rejected, partial_rejected }`
- **动机**: 与本期「修改入口」(§3.1) 的可修改状态白名单 (含 `rejected` / `partial_rejected`) 对齐, 给出"放弃当前申请"的另一种出口
- **后端**: 已确认 `terminateTicket` 接口对 `rejected` / `partial_rejected` 主单可正常处理, 前端只需放开按钮禁用
- **范围**: 仅放开按钮禁用; 终止确认弹窗、终止后状态刷新逻辑均沿用现有实现, 不做改动

### 3.5 非本年预测截止期限制 (新)

#### 3.5.1 接口调用时机

- **仅在「资源预测添加」业务逻辑中**调用 `report_deadline` 接口
- 不做全局缓存 / 不在 App 启动时拉取
- 列表组件按需调用 (跟随业务侧或服务侧列表的加载)

#### 3.5.2 资源预测添加页 (`views/business/resource-plan/add/`)

- 进入页面时拉取 `report_deadline`, 与前端「非本年起始日」常量一起决定行为:
  - **任一为空** → 申报期, 期望到货日期 picker 无限制
  - **均非空 且 当前日期 > deadline** (deadline 次日起) → 评审期, 期望到货日期 picker **禁选 ≥ 非本年起始日的日期** (即只能选 ≤ `2026-12-31`)
  - **均非空 且 当前日期 ≤ deadline** → 申报期, 无限制
- 被禁选状态下需给出明确提示文案 (示例): 「预算评审期间, 不允许提交 2027 及之后的预测; 如需调整已有单据请使用单据详情页的「修改需求」入口」
- 接口失败时**按申报期兜底** (避免误拦截), 控制台 warn 记录

#### 3.5.3 资源预测列表 (业务侧 + 服务侧)

- 业务侧与服务侧**复用同一列表组件**, 截止期相关的禁用逻辑在该公共组件内统一控制 (资源侧无此列表, 不涉及)
- 行级判定: 单行 `期望到货日期 ≥ 非本年起始日` 视为「非本年行」
- 评审期内, 对所有「非本年行」:
  - **行内操作**全部禁用: 编辑 / 撤销 / 删除 / 其他单行操作
  - **批量操作**: 若选中行**包含**「非本年行」, 则批量操作 (批量撤销等) 按钮禁用; 或允许选中但提交时校验并提示拦截 (具体方式在 design 阶段定)
  - 禁用项需 tooltip 提示原因
- 申报期 (任一为空) → 列表无任何禁用, 行为不变

#### 3.5.4 解除限制 (Phase 3, 评审完成)

- 前端**不需要单独实现** Phase 3 逻辑
- 后端将 `deadline` 配置回空字符串 → 前端自动按申报期处理 (无任何禁用)
- 若后续需要调整年度区间 (`2027-01-01` → `2028-01-01` 等), 前端**通过修改常量配置**完成, 不依赖后端

## 4. 业务规则

| 规则 | 说明 |
|---|---|
| 入口可见性以详情接口实时返回为准 | 单据状态在详情页轮询 (30s) 期间发生变化, 入口可见性需跟随刷新 |
| 修改人限制 | 不做额外人员限制, 沿用现有体系 |
| 修改后子单的生命周期 | 由后端定义, 提交后以**重新拉取的详情接口数据**为准刷新单据状态 |
| 截止期判定基准 | 客户端当前日期, 不引入时区计算; 全部按 `YYYY-MM-DD` 字符串比较 |
| 截止期与修改入口的关系 | 修改入口和修改页提交**不受截止期影响** (与 §3.1 / §3.2 一致) |
| 接口空值兜底 | `deadline` 为空 / 接口失败 → 按申报期处理 (无限制); 非本年起始日常量为空 → 同理 |

## 5. 边界与异常

- **详情接口加载失败**: 修改入口不显示
- **`report_deadline` 接口失败 / 超时**: 按申报期兜底, 不阻断用户操作
- **修改页表单校验未通过**: 沿用新增页的字段级校验提示, 阻断提交
- **修改提交失败 (网络 / 后端报错)**: 保留用户已编辑内容, 给出错误提示
- **轮询中状态翻转**: 修改页内若原单据被推进到不可修改态, 由后端提交时拦截, 前端展示后端错误
- **列表中已撤销 / 已完成的非本年行**: 仍按「非本年行」处理 (这些行本来也无可用操作, 不会出现可见冲突)

## 6. 非目标 (本迭代不做)

- 不做「修改历史 / 操作日志」展示
- 不做修改对比 (diff) 视图
- 不改新增页本身的字段、校验、布局 (除日期 picker 的禁选规则外)
- 不调整子单列表 / 审批信息区的展示
- 不做资源预测以外其他单据类型 (主机 / 网络等) 的修改入口
- 不做 `report_deadline` 全局缓存 / 全局拉取
- 不做修改入口 / 修改页内的截止期日期禁选

## 7. 验收标准 (前端视角)

### 7.1 修改入口

- [ ] 详情页在「可修改」状态下显示「修改需求」按钮, 在「不可修改」状态下不显示
- [ ] 四种可修改状态 (全部驳回 / 全部失败 / 部分失败无通过 / 已撤销) 均能进入修改页
- [ ] 三种不可修改状态 (任一通过 / 审批中 / 已完成 / 已终止) 均不显示入口
- [ ] 修改页表单结构与新增页一致, 字段全部正确回填
- [ ] 修改页可正常提交, 提交成功后回到详情页, 单据状态按后端反馈刷新
- [ ] 修改页可取消, 取消不影响原单据状态
- [ ] 详情接口加载失败 / 数据缺失时, 入口隐藏

### 7.2 子单列表「终止」按钮

- [ ] 主单状态 ∈ { failed / partial_failed / rejected / partial_rejected } 时, 子单列表「终止」按钮可点击
- [ ] 其余主单状态下, 「终止」按钮 disabled
- [ ] 点击「终止」沿用现有确认弹窗与刷新逻辑, 不出现新增 / 残留 UI

### 7.3 截止期限制

- [ ] 申报期 (`deadline` 空或未到): 添加页期望到货日期 picker 无限制; 列表所有操作正常
- [ ] 评审期 (`deadline` 非空且已到): 添加页期望到货日期 picker 禁选 ≥ 非本年起始日, 有明确提示文案
- [ ] 评审期: 业务侧 + 服务侧列表中, 「非本年行」行内操作 + 含非本年行的批量操作均禁用并有 tooltip
- [ ] 评审期: 修改入口仍可见可点, 修改页可正常提交 2027 单据
- [ ] 「非本年起始日」前端常量改为空字符串 → 即使评审期内也不做限制 (自测路径)
- [ ] `report_deadline` 接口失败 → 按申报期兜底, 控制台 warn

## 9. 影响范围 (前端文件预估)

### 9.1 修改入口

- `views/ticket/children/resource-plan/detail/index.vue` — 详情头部加入「修改需求」入口
- **新增独立修改页** (整体 copy 新增页 `views/business/resource-plan/add/`), UI 与交互保持一致, 支持原单据数据回填
- **新增路由**: 在**老版集中式路由** `router/module/business.ts` 中, 紧邻 `BizResourcePlanAdd` 添加 `modify` 路由

### 9.2 截止期限制

- **新增前端常量**: 「非本年起始日」(位置 design 阶段定, 备选 `views/business/resource-plan/constants.ts` 或类似)
- **新增 store action**: `getReportDeadline()` 调用 `GET /api/v1/woa/plans/resources/tickets/report_deadline`
- `views/business/resource-plan/add/` — 进入时拉取 deadline, 期望到货日期 picker 加禁选规则与提示
- 资源预测**公共列表组件** (业务侧 / 服务侧共用) — 按需拉取 deadline, 应用行级禁用规则 + 批量禁用规则 (具体组件位置 design 阶段定位)
