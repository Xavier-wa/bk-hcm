# Design - 资源预测 2027 CVM 预算提报 · 修改入口 + 截止期限制

- **Requirement**: req-resource-plan-2027-cvm-budget
- **Iteration**: feat-resplan-cvm-reqmodify
- **设计稿**: 无 Figma, 按本文档默认方案

> 本阶段只描述产品交互/视觉/状态流转, 不写技术实现 (组件选型/路由命名/接口字段等留到 api / coding 阶段)。
>
> 本迭代两个功能点 **互相独立**, 修改入口 (§1-§2) 不受截止期 (§3) 限制影响。

## 1. 详情页「修改需求」入口

### 1.1 位置 (两处都展示)

入口同时出现在以下两个位置, 同步显隐, 同步可点击:

**位置 A — 审批节点信息面板**
- 文件: `components/resource-plan/applications/detail/approval/index.tsx`
- 位置: 与状态图标 / `status_name` / `renderAuditStatus()` 同行, 放在该 `Panel` 内的**右侧操作区**
- 视觉对齐: 状态信息靠左, 按钮靠右; 与现有 `error-message` 等元素垂直居中对齐

**位置 B — 子单信息面板标题栏**
- 文件: `views/ticket/children/resource-plan/sub-ticket/sub-ticket-list.vue`
- 位置: `Panel` 的 `#title-extra` 插槽中, 与「失败单据处理 / 复制CRP待审批链接 / 终止 / 批量审批」**同一行的按钮组**内
- 顺序: 放在按钮组**最右侧** (排在「批量审批」之后, 作为该单据级别的主操作)

### 1.2 视觉

- **按钮文案**: 「修改需求」
- **按钮主题**: 沿用按钮组现有风格 (默认 `bk-button` 无主题, 与「失败单据处理 / 终止」等同级操作风格一致), 不使用 `theme="primary"` 避免与「批量审批」抢主操作位
- **间距**: 与同行按钮保持 `margin-left: 21px`, 与现有按钮间距一致

### 1.3 显隐规则 (与 PRD §3.1 / api.md §3 一致)

- 仅在**业务视角 + 可修改状态**下可见 (不在前端按 `demand_class` 过滤, 资源预测仅 CVM / CA, overwrite 接口按白名单拦截)
- 「可修改状态」: 主单 status ∈ { rejected, partial_rejected, failed, partial_failed, revoked } 且子单无 done (与后端 MR 3093 对齐)
- 两个位置**同步显隐**, 不允许出现「一处可见、另一处隐藏」的情况
- 详情接口轮询 (30s) 后状态翻转, 按钮可见性需实时跟随刷新, 不缓存
- 主单详情 loading / 失败时, 按钮默认不展示; 子单列表 undefined / [] 均按无 done 处理 (允许)

### 1.4 交互

- 点击「修改需求」 (任一位置): 直接跳转到修改页 (无二次确认弹窗)
- 两处入口行为完全一致 (跳转目标、参数、行为)
- 跳转过程不显示额外 loading; 修改页自行处理首屏加载

## 2. 修改页

### 2.1 整体布局

与新增页 (`views/business/resource-plan/add/`) **100% 对齐**:

```
┌─────────────────────────────────────────┐
│  Header: ← 修改资源预测                  │   ← 唯一文案差异点
├─────────────────────────────────────────┤
│  Basic (基本信息)                        │
├─────────────────────────────────────────┤
│  List (资源需求列表, 含新增/修改/删除)    │
├─────────────────────────────────────────┤
│  Memo (备注)                             │
├─────────────────────────────────────────┤
│  [取消]  [提交]                          │
└─────────────────────────────────────────┘
```

### 2.2 与新增页的差异点 (穷举)

| 维度 | 新增页 | 修改页 |
|---|----|----|
| Header 文案 | 新增资源预测 | 修改资源预测 |
| Header 返回箭头目标 | 资源预测列表 | 原单据详情页 |
| 表单初始值 | 空 / 默认值 | **由原单据数据回填** |
| 提交接口 | 现有新增接口 | **新接口** (api 阶段对齐) |
| 提交成功后跳转 | 默认行为 (沿用现有) | **跳回原单据详情页** + 触发详情页重新拉取 |
| 取消按钮目标 | 沿用现有 | **回到原单据详情页** |
| 二次确认弹窗 | 无 | 无 (保持一致) |

**其他所有维度** (字段顺序、校验规则、子需求增删改交互、备注交互、Button 区位置、loading 表现、错误提示样式等) **与新增页完全一致**。

### 2.3 数据回填

- **时机**: 修改页加载时立即拉取原单据详情, 拉取期间页面整体 `bk-loading`
- **回填范围**: 基本信息、资源需求列表所有子项、备注
- **用户感知**: 数据到位后表单直接呈现已填充状态, 不显示中间空态; 后续编辑与新增完全一致

### 2.4 子需求编辑行为

- 已存在的子需求: 可**修改 / 删除**, 也可**新增**新的子需求
- 子需求的内部交互 (类型选择、规格、数量等) 完全沿用新增页对应组件 (`components/resource-plan/add`)
- 不展示「这是已驳回 / 已失败的子单」之类的状态标注 (本迭代非目标)

### 2.5 校验

- 沿用新增页全部字段级校验规则
- 提交前必须通过 `Basic / List / Memo` 三处 `validate()`, 任一失败则阻断提交并定位到首个错误字段 (与新增页一致)

### 2.6 提交反馈

- **成功**: 走现有成功提示机制 (toast「提交成功」之类, 文案沿用新增) → 自动跳回原详情页 → 详情页拉取最新数据并刷新审批 / 子单状态
- **失败**: 沿用现有错误 toast / message 机制; 表单已编辑内容保留, 用户可改后再次提交
- **状态翻转拦截**: 若提交瞬间原单据已被推进到不可修改态 (例如管理员强制通过某子单), 后端拦截返回错误, 前端按错误 toast 提示, 不做客户端预拦截

### 2.7 取消

- 「取消」按钮位置、文案沿用新增页
- 点击取消: 直接跳回原单据详情页 (不弹「确认放弃修改」弹窗, 保持与新增页一致)

## 3. 子单列表「终止」按钮可用状态

- **位置**: 子单列表标题右侧的「终止」按钮
- **可点击状态白名单**: `failed` / `partial_failed` / `rejected` / `partial_rejected`
- **实现方式**: 抽出常量 `TERMINATABLE_STATUSES`, `disabled = !TERMINATABLE_STATUSES.includes(ticketStatus)`, 替代原硬编码 `||` 链
- **UI / 文案**: 不动 (按钮文本「终止」, 确认弹窗复用)
- **与「修改需求」入口的关系**: 两个入口出现时机有重叠 (rejected / partial_rejected) — 用户可选择「修改后重提」或「直接终止」, 互不影响

## 4. 非本年预测截止期限制

### 4.1 概念回顾 (参见 prd.md §2)

- **申报期**: `deadline` 为空 OR 当前日期 < `deadline` → **无任何限制**
- **评审期**: `deadline` 非空 且 当前日期 ≥ `deadline` → **启用限制**
- **任一空值兜底**: `deadline` 为空 OR 「非本年起始日」常量为空 → 视为申报期, 不限制

### 4.2 资源预测添加页 (`views/business/resource-plan/add/`)

#### 3.2.1 期望到货日期 picker 行为

| 阶段 | DatePicker 行为 |
|---|---|
| 申报期 | 无禁选, 可选任意未来日期 (含 2027 及之后) |
| 评审期 | **禁选 ≥ 非本年起始日 的日期** (默认 `2027-01-01` 起整段禁选, 即只能选 ≤ `2026-12-31`) |

- 禁选实现走 bkui `DatePicker` 的 `disabledDate` 钩子, 不通过校验报错
- 禁选日期在面板上以默认置灰样式呈现 (沿用 bkui 默认), 不引入自定义样式

#### 3.2.2 评审期提示文案

picker 旁边 (label 行右侧 or 字段下方提示位) 增加常驻文案:

```
预算评审期间, 不允许提交 2027 及之后的预测; 如需调整已有单据, 请使用单据详情页的「修改需求」入口
```

- 仅评审期展示, 申报期隐藏
- 文案使用 `t(...)` 国际化, 颜色用项目既有「次要文字」色
- 「2027」按非本年起始日动态拼接 (取常量首段年份), 不硬编码
- 不弹 toast / 不阻断提交流程, 用户即使尝试硬填也由 picker 禁选层兜底

#### 3.2.3 接口失败兜底

- `report_deadline` 接口失败 → 按申报期处理, 无禁选无提示
- 不弹错误 toast (不打扰用户)
- 控制台 warn 记录, 便于排查

### 4.3 资源预测列表 (业务侧 + 服务侧公共组件)

#### 3.3.1 「非本年行」识别

- 单行 `expect_time` (期望到货日期) ≥ 非本年起始日 即视为「非本年行」
- 申报期: 无此概念, 所有行行为不变
- 评审期: 按上述规则识别

#### 3.3.2 行内操作禁用

| 列 / 操作 | 评审期 + 非本年行 |
|---|---|
| 行内操作按钮组 (编辑 / 调整 / 撤销 / 删除 等) | **全部禁用** |
| 行选中 checkbox | 仍可选 (避免 UX 突兀), 但勾选后批量操作按钮做拦截 (见 §3.3.3) |
| 单元格点击进入详情 | 不影响, 详情页内的「修改需求」入口可见性走 §1 规则 |

- 禁用按钮 hover 时通过 `bk-tooltips` 提示原因: 「预算评审期间, 期望到货日期为 2027 及之后的单据已锁定操作」
- 文案中 「2027」 按起始日动态拼接

#### 3.3.3 批量操作禁用

- 选中行若**包含**「非本年行」: 顶部批量操作按钮 (批量撤销 / 批量延期等) 全部**禁用**
- 禁用按钮 hover 提示: 「所选包含 2027 及之后的非本年预测, 评审期内已锁定操作; 请取消勾选后再批量操作」
- 不做「自动过滤非本年行后允许批量」之类的复杂行为 (本期非目标)

#### 3.3.4 接口失败兜底

- `report_deadline` 接口失败 → 按申报期处理, 所有行无禁用
- 与 §3.2.3 一致, 不弹 toast

### 4.4 修改入口 / 修改页 (重申)

- 详情页「修改需求」入口: **不受**截止期影响, 评审期内仍可见可点
- 修改页期望到货日期 picker: **不应用** §3.2.1 的禁选规则 (修改页不拉 `report_deadline` 接口)
- 评审期内通过「修改需求」入口重提的 2027 单据: 后端正常接收 (前端不拦截)

### 4.5 状态流转 (截止期视角)

```
[添加页 / 列表页 挂载]
  └─ 拉取 report_deadline
      ├─ 接口失败 / deadline = '' ─→ 申报期, 无限制
      ├─ now ≤ deadline           ─→ 申报期, 无限制
      └─ now > deadline (精确到秒)
          └─ 起始日常量 = '' ─→ 申报期, 无限制 (前端关闭限制)
          └─ 起始日常量非空 ─→ 评审期
              ├─ 添加页: picker 禁选 ≥ 起始日 + 评审期提示
              └─ 列表页: 非本年行禁用所有行内/批量操作 + tooltip
```

## 5. 状态流转 (前端视角 - 修改入口)

```
[详情页]
  ├─ 状态不满足 ─→ 不显示「修改需求」入口
  └─ 状态满足
      └─ 点击「修改需求」
          └─→ [修改页] (loading → 回填完成)
                ├─ 编辑表单
                │   ├─ 校验失败 ─→ 错误提示 (页内)
                │   └─ 校验通过
                │       └─ 点击「提交」
                │           ├─ 成功 ─→ toast → 跳回[详情页]并刷新
                │           └─ 失败 ─→ toast, 表单保留
                └─ 点击「取消」 ─→ 跳回[详情页]
```

## 6. 无障碍 / 国际化

- 所有新增文案 (按钮 / Header / toast / tooltip / 评审期提示) 走项目 `useI18n()` `t(...)`, 不硬编码
- 评审期提示与 tooltip 中的年份按非本年起始日动态拼接, 国际化时使用占位符 (例: `t('预算评审期间, 不允许提交 {year} 及之后的预测...', { year: '2027' })`)
- 颜色 / 对比度沿用项目既有主题, 不引入新色板

## 7. 阻塞问题

无 — 两个功能点的默认方案均已与用户对齐, 可进入 coding。
