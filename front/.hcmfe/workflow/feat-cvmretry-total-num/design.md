# Design: CVM 申请 - 修改需求重试 - 数量显示优化

## 设计稿状态

- **无设计稿**
- **原因**：本次为纯逻辑修复，仅修改前端字段引用（`origin_num` → `total_num`），无 UI / 交互变更
- **UI 参照**：保持现有页面布局和交互不变，CVM 申请-修改需求重试页面（[TAPD 需求描述附截图](https://<TAPD_HOST>/tapd_fe/69995598/story/detail/1069995598135132530)）

## 变更说明

### 当前页面元素

修改需求重试页面包含以下与数量相关的元素：

1. **需求数量展示区域**（如"需求总数：X"文本）
   - 当前使用 `origin_num` → 改为使用 `total_num`
2. **数量输入框**（用于修改需求数量）
   - 当前回填 `origin_num` → 改为回填 `total_num`
3. **提交时的请求参数**
   - 当前提交 `origin_num` 值 → 改为提交 `total_num` 值

### 视觉变更

本次不涉及任何 UI/UX 变化，仅修改数据源字段。

## 交互流程

保持现有交互流程不变：
1. 用户进入修改需求页面
2. 页面加载「需求子单」或「修改需求」数据
3. 数量展示和输入框回填使用 `total_num`
4. 用户修改可用区/机型/数量等参数
5. 提交时使用实际调整后的数量
