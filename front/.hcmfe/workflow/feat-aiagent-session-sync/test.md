# feat-aiagent-session-sync 测试清单

> 工作流: `feat-aiagent-session-sync`（lite: coding → test → done）
> 关联文档: `coding.md`、需求文档 `front/docs/reqs/多会话状态同步.md`
> 交付目标: **读一致性** —— 多入口（浮窗助手 + 全屏 chatbot）/ 多标签页同时打开同一会话时，非活跃处能展示最新会话内容。

## 验证范围

- 功能边界:
  - F-001 可见/聚焦刷新：面板重新可见、标签页切回 / 窗口聚焦时，刷新「当前会话」历史（300ms 去抖）。
  - F-002 提交/续跑前校验：`sendMessage` 携带 `resumeValue`（续跑/卡片确认）时，先刷新当前会话再发起；刷新后照常提交。
  - F-003 跨标签页广播：`BroadcastChannel('hcm-chatbot-sync')`，一处写完成广播 `session-updated`，其他同会话且空闲实例自动刷新。
  - F-004 in-flight 窗口锁定：动作发起即广播 `session-busy`，其它「持有 pending 可交互卡片」的同会话实例立即锁定该卡片（黄色横幅 + 按钮禁用，不折叠为「已选择」摘要）；完成后 `session-updated` 解锁并刷新；20s 兜底自动解锁。
  - 刷新守卫：无选中会话 / 正在流式输出（`isChatting`）/ 空会话 → 跳过。
  - 快照替换：`fetchHistory` 收到 `MESSAGES_SNAPSHOT` 时先清空再填充（替换式），刷新无重复追加、无明显闪烁。
- 不在范围:
  - 409 冲突的专门处理与冲突 UX（本期沿用现有错误渲染路径，标注为后续增强）。
  - 后端「查单接口 `bk_biz_id` 类型不兼容」问题（需后端配合，前端本期不改）。
  - 会话列表跨端实时增删改 / 排序同步。
  - 轮询（明确不采用）。

## 测试环境

- 前端入口: `<对应业务的测试环境地址，由执行人在测试时确认；不要把具体域名写入仓库>`

  - 浮窗入口: 挂载了 `ai-assistant` 组件的业务页（如主机申领相关页面），通过悬浮球 / `Cmd|Ctrl+I` 唤起。
- 测试账号: `<test_account>`（需有对应业务权限，可发起主机申领会话）
- 数据准备:

  - 需要两个可同时打开的入口来复现「多会话同时打开」：推荐「同一浏览器两个标签页分别打开全屏 chatbot」，或「一个标签页浮窗 + 另一标签页全屏」，指向同一 `sessionCode`。

## 用例清单

### P0 - 主流程（必测）

| ID | 场景 | 前置 | 操作 | 期望 | 回滚 |
|----|------|------|------|------|------|
| P0-01 | 切回标签页刷新读一致性 | 同一会话在标签页 A、B 同时打开 | 在 A 发送一条消息并等待回复完成；切到 B 标签页（触发 focus/visibilitychange） | B 在约 300ms 内自动拉取最新历史，展示 A 新增的问答；无重复气泡、无长时间全屏 loading | 无需回滚 |
| P0-02 | 浮窗重新展开刷新 | 浮窗已选中某会话，收起面板；在全屏入口对同一会话推进对话 | 重新唤起浮窗（悬浮球 / 快捷键） | 浮窗展示该会话最新内容（含全屏处的新问答） | 无 |
| P0-03 | 续跑/提交前校验（F-002） | A、B 同开同一会话，存在一张待确认卡片；在 A 完成该卡片对应操作（推进 checkpoint） | 在 B 点击同一张（本地仍为待确认的）卡片进行确认/续跑 | 发起前先刷新：卡片更新为最新态（已消费/已提交）；若服务端因已推进返回 409，走现有错误提示，不出现「基于过期 checkpoint 静默重复提交成功」 | 无 |
| P0-04 | 跨标签页广播自动刷新（F-003） | A、B 同开同一会话，B 处于空闲（非流式） | 在 A 发送消息并完成 | B **无需手动聚焦**即在写完成后自动刷新出最新问答 | 无 |
| P0-05 | 流式输出中不被打断（isChatting 守卫） | 在 B 发起一条消息，回复正在流式输出中 | 此时切走再切回 B / A 触发一次广播 | B 正在进行的流式输出不被中断、不被历史快照覆盖；刷新被跳过 | 无 |
| P0-06 | in-flight 窗口锁定防重复点击（F-004 核心） | A、B 同开同一会话，当前存在**待操作卡片**（方案推荐 / 预提单 / 确认提交 / 账号选择 / HITL 其一） | 在 A 点击「选择方案/确认/提交」等，**请求进行中（5-10s，未返回）时**观察 B | B 该卡片**瞬间**出现黄色横幅「该会话正在其它页面操作中…」且操作按钮全部置灰，无法在窗口期重复点击/提交；卡片主体仍可见（不误显示为绿色「您已选择」） | 无 |
| P0-07 | 完成后解锁并刷新（F-004） | 承接 P0-06，A 的请求已返回完成 | 观察 B | B 横幅消失、锁定解除；`session-updated` 触发刷新，B 展示与 A 一致的最新态（如卡片变已消费/已提交、出现后续气泡） | 无 |

### P1 - 异常分支（必测）

| ID | 场景 | 前置 | 操作 | 期望 |
|----|------|------|------|------|
| P1-01 | 首页空态不发无谓请求 | 处于首页空态（未选中任何会话） | 切走再切回标签页 / 收起再展开浮窗 | 不触发 `/history` 请求（无选中会话守卫生效），页面保持空态 |
| P1-02 | 刷新接口失败静默降级 | 选中一个有历史的会话；拦截 `/history` 使其失败 | 触发可见/聚焦刷新 | 保留原有本地消息，不清空、不弹全局错误；控制台有一条 warn |
| P1-03 | 高频切换去抖 | 选中一个有历史的会话 | 300ms 内快速多次 alt-tab / focus | 仅触发一次 `/history` 刷新（去抖生效），不产生请求风暴 |
| P1-04 | 普通首轮发送不额外刷新 | 选中会话，正常输入普通消息（无卡片续跑） | 发送 | 发送链路不额外多一次 `/history`（仅 `resumeValue` 续跑才前置刷新） |
| P1-05 | 空会话不刷新 | 选中一个 `sessionContentCount=0` 且本地无消息的空会话 | 触发可见/聚焦刷新 | 跳过刷新，不发 `/history` |
| P1-06 | 无 pending 卡片会话不受锁定影响 | A、B 同开同一会话，B 当前**无**待操作卡片（纯文本历史） | 在 A 发送消息（触发 session-busy） | B 无任何锁定横幅 / 视觉变化（只锁有 pending 卡片的会话）；文本输入框保持可用（cards_only 口径） | 无 |
| P1-07 | 发起端异常关闭 20s 兜底解锁 | A、B 同开同一会话且有 pending 卡片；A 发起动作后**强制关闭 A 标签页**（不发 `session-updated`） | 在 B 观察被锁定的卡片 | B 卡片最多 20s 后自动解除锁定（横幅消失、按钮恢复可点），不会永久卡死 | 无 |

### P2 - UI 细节 / 兼容（按需）

- [ ] 刷新为「替换式」：切回后历史一次性替换，无消息重复追加、无明显闪烁/跳动。
- [ ] 面板收起状态下浮窗不响应可见/聚焦刷新（仅展开时刷新）。
- [ ] 组件卸载后 `visibilitychange`/`focus` 监听已注销、去抖 `cancel()`，无内存泄漏 / 无卸载后仍触发刷新。
- [ ] `BroadcastChannel` 不可用的浏览器（或隐私模式）下功能降级：F-001/F-002 仍工作，F-003/F-004 静默失效不报错（其它标签页不锁定，退化为完成后聚焦刷新）。
- [ ] F-004 锁定态视觉：黄色横幅在浮窗窄容器与全屏宽容器下均正常展示；预提单/确认提交卡片的「全屏最大化」浮层内按钮在锁定期同样禁用。
- [ ] 回归既有路径：切换会话（`switchSession`）、深链直达、删除会话后自动切换、新建会话，历史加载均正常。
- [ ] 单标签页单入口正常使用不受影响（无多余请求、无异常刷新）。
