# fix-host-apply-link-biz-mismatch 测试清单

> 工作流: `fix-host-apply-link-biz-mismatch`
> 关联文档: [需求文档](../../../docs/reqs/外链业务不匹配.md) / [coding.md](./coding.md) / TAPD 1069995598137480239

## 验证范围

- 功能边界: 外链进入时的全局业务初始化优先级；主机申请单据详情页与主机回收单据详情页的业务归属与接口业务；已移除的业务版本号兜底逻辑
- 不在范围: 业务选择器的交互样式与收藏排序、单据审批流程本身、后端业务校验、其它未携带 `bkBizId` 的页面

## 测试环境

- 前端入口: `<对应业务的测试环境地址，由执行人在测试时确认>`
- 测试账号: `<test_account>`（需要一个对多业务有权限、且对某一业务无权限的账号，用于 P1-03）
- 数据准备:
  - 一条主机申请单，处于可审批状态（当前审批人为测试账号），记其单据 id 为 `<order_id>`、所属业务为 `<order_biz>`
  - 另一个测试账号有权限的业务 `<other_biz>`，且 `<other_biz>` 在有权限业务列表中排在 `<order_biz>` 之前（用于复现兜底取首项的场景）
  - 一条主机回收单据（`HostRecycleDocDetail`），用于 P1-04 的同类页面回归
  - 清缓存方式：浏览器无痕窗口，或手工清除 localStorage 中的 `bizs`、`bizs_version` 两个键
  - 观察方式：全程打开 DevTools Network 面板，核对请求 URL 中 `bizs/<id>/` 段的业务 id

## 用例清单

### P0 - 主流程（必测）

| ID | 场景 | 前置 | 操作 | 期望 | 回滚 |
|----|------|------|------|------|------|
| P0-01 | 无本地缓存时外链进入保持链接业务 | 无痕窗口，未访问过系统 | 直接打开 `.../host-application/detail/<order_id>?bizs=<order_biz>&bkBizId=<order_biz>&creator=<test_account>&resource_type=QCLOUDCVM` | 顶部业务选择器显示 `<order_biz>`；地址栏 `bizs` 仍为 `<order_biz>`，未被改写为其它业务 | 关闭窗口 |
| P0-02 | 本地缓存业务与链接业务冲突时以链接为准 | 先在系统内把业务切到 `<other_biz>`，再打开同一浏览器新标签 | 打开上述外链 | 顶部业务切换为 `<order_biz>`，地址栏 `bizs` 保持 `<order_biz>` | 无 |
| P0-03 | 存量链接两个业务不一致时以单据业务为准 | 无痕窗口 | 打开 `...detail/<order_id>?bizs=<other_biz>&bkBizId=<order_biz>&...`（手工构造，模拟已被改写后分享出去的链接） | 页面停留在单据详情页不被踢回列表；顶部业务与地址栏 `bizs` 均对齐为 `<order_biz>`；详情数据正确显示 | 无 |
| P0-04 | 审批请求落在单据所属业务 | 处于 P0-03 的页面，当前账号为审批人 | 点击「立即处理」→ 同意 → 提交 | Network 中 `task/audit/apply/ticket` 请求路径为 `/api/v1/woa/bizs/<order_biz>/...`，不出现 `<other_biz>`；审批成功提示，5 秒后审批流刷新 | 该单据审批状态变更，需准备可重复使用的单据或换单重测 |
| P0-05 | 详情页全部接口使用单据业务 | 进入 P0-03 的页面 | 观察页面加载时的全部请求 | `task/get/apply/ticket`、`task/findmany/apply`、`task/findmany/apply/device`、`task/get/apply/ticket/audit` 路径中的业务 id 均为 `<order_biz>`；「查看变更记录」打开后 `task/find/apply/record/modify` 同样为子单业务 | 无 |

### P1 - 异常分支（必测）

| ID | 场景 | 前置 | 操作 | 期望 |
|----|------|------|------|------|
| P1-01 | 详情页手动切换业务不报错 | 处于单据详情页 | 点击顶部业务选择器，切到 `<other_biz>` | 页面不报错、不白屏；跳转到 `<other_biz>` 的单据列表页；地址栏 `bizs` 为 `<other_biz>` 且不再携带 `bkBizId` |
| P1-02 | 多标签页缓存互不干扰 | 标签页 A 中把业务切为 `<other_biz>` | 在标签页 B 打开 `bizs=<order_biz>&bkBizId=<order_biz>` 的外链 | 标签页 B 的业务为 `<order_biz>`，不被标签页 A 写入的缓存影响 |
| P1-03 | 无权限业务不静默切换 | 使用对 `<order_biz>` 无权限的账号 | 打开该业务下的单据详情外链 | 不静默切到其它有权限业务；走现有无权限提示流程；无法发起审批 |
| P1-04 | 主机回收单据详情同类回归 | 准备一条回收单据 | 从单据列表进入回收单据详情，查看基本信息与执行记录 | 页面正常展示；`task/findmany/recycle/order`、`task/findmany/recycle/host`、`task/findmany/recycle/detect/step` 路径中的业务 id 为该回收单据所属业务 |
| P1-05 | 无业务参数进入时回落既有逻辑 | 无痕窗口 | 直接打开业务视角首页（地址不带 `bizs`、不带 `bkBizId`） | 回落到本地缓存业务；本地也无缓存时取有权限业务列表首项，行为与改动前一致 |
| P1-06 | 非业务视角页面不受影响 | 任意 | 进入工作台（`/service/`）下的主机申请单据详情 | 接口路径不带 `bizs/<id>/` 前缀，页面与改动前一致 |
| P1-07 | 缺少 `bkBizId` 的存量链接不拼出非法路径 | 无痕窗口 | 手工去掉 `bkBizId`，只留 `?bizs=<order_biz>` 打开单据详情 | 接口路径为 `bizs/<order_biz>/`，**不出现 `bizs/NaN/` 或 `bizs/0/`**；页面正常加载（回退到全局业务，与改动前行为一致）。主机回收单据详情同样验证一次 |
