# Test - CVM申请-修改需求重试优化

## 验证项

### P0 - 修改需求重试场景

**数据准备**：
- 准备一个已部分生产的 CVM 申请子订单（存在未生产数）
- 子订单状态允许修改

**操作步骤**：
1. 进入"修改申请"页面（通过工单列表点击重试/修改）
2. 在"未生产需求调整"区域，点击"编辑"按钮
3. 打开浏览器 DevTools，观察 Network 面板
4. 查看 `findmany/config/cvm/charge_type/device_type` 接口请求

**期望结果**：
- [ ] 请求体中包含 `suborder_id` 字段，值为当前子订单 ID
- [ ] 机型列表能正确加载，展示可用机型
- [ ] 能正常选择机型并提交修改

### P0 - 新建申请场景（回归）

**操作步骤**：
1. 进入新建 CVM 申请页面
2. 点击机型选择区域的"添加"按钮
3. 观察 Network 面板中的 `findmany/config/cvm/charge_type/device_type` 请求

**期望结果**：
- [ ] 请求体中**不包含** `suborder_id` 字段
- [ ] 机型列表正常加载，功能不受影响

### P1 - 边界验证

**操作步骤**：
1. 修改申请页打开机型弹窗后，切换可用区
2. 观察每次 `findmany/config/cvm/charge_type/device_type` 请求

**期望结果**：
- [ ] 每次请求均携带相同的 `suborder_id`

**测试结果**：
- ✅ 切换可用区不会重新请求接口，经确认此为预期行为（非 bug）

## 验证结论

| 验证项 | 结果 | 备注 |
|--------|------|------|
| P0 - 修改需求重试场景 | ✅ 通过 | 接口正确携带 `suborder_id`，功能正常 |
| P0 - 新建申请场景 | ✅ 通过 | 未携带 `suborder_id`，符合预期 |
| P1 - 边界验证 | ✅ 通过 | 切换可用区不重新请求为预期行为 |
