# PRD — 海垒申领界面及修改界面增加子网网段"可用IP"数量显示

> 来源单据：story `1069995598137153583`（`https://<TAPD_HOST>/tapd_fe/69995598/story/detail/1069995598137153583`）
> 关联原始需求：`1069995598132811653`（短 ID 132811653）

## 1. 需求概述

实际交付场景中多次因所选子网 IP 不足而失败，业务只能登录云厂商控制台查询剩余 IP，再回海垒调整网段。目标是在资源申领界面与未生产需求调整界面的子网下拉中，内联展示每个网段的"可用 IP"数量，让用户一次选到 IP 足够的子网，避免因 IP 不足反复改单、交付失败。

## 2. 用户故事

**故事 1**：作为自研云资源申领人，我想要在资源申领界面的子网下拉里看到每个网段的可用 IP 数量，以便于一次选到 IP 足够的子网，避免因 IP 不足反复改单、交付失败。

**故事 2**：作为账号负责人 / 运营，我想要在未生产需求调整界面的子网下拉里看到每个网段的可用 IP 数量，以便于调整未生产需求时直接判断网段是否还能承载剩余生产数量。

## 3. 功能需求

| 编号 | 功能描述 | 优先级 |
| --- | --- | --- |
| F-001 | 子网下拉选项内联展示"可用IP"数量，形如 `subnet-xxx | cvm_use_199 | 可用IP: 200` | P0 |
| F-002 | 异常 / 无数据时（`available_ip_count` 未取到）显示 `可用IP: 0` | P1 |
| F-003 | 子网选择器附近注明口径：可用IP 为云厂商未分配可用 IP 数 | P1 |

## 4. 业务规则

- R-001：可用 IP 采用云厂商标准口径（未分配可用 IP 数）。
- R-002：仅覆盖自研云场景。
- R-003：下拉选项内联追加，不做选中后单列。
- R-004：只展示，不因可用 IP 不足禁用选项或拦截提交；可用 IP 为 0 仍可选可提交。
- R-005：查询失败与可用 IP 为 0 在 JSON 层不区分，统一显示 `可用IP: 0`（后端 `available_ip_count` 为 `uint64`，失败/未取到均返回 `0`）。

## 5. 验收标准

- AC-001：Given 用户在资源申领或未生产需求调整界面展开子网下拉，When 可用 IP 正常返回，Then 每个选项内联显示 `可用IP: X`。
- AC-002：Given 用户选择带可用 IP 的子网，When 提交申领或修改，Then 不影响原有选择与提交流程。
- AC-003：Given 查询失败 / 无权限 / 无数据，When 展开下拉，Then 该选项显示 `可用IP: 0`。
- AC-004：Given 自研云子网，When 展示，Then 仅自研云子网显示可用 IP。
- AC-005：Given 界面展示可用 IP，When 用户查看，Then 能看到口径说明「可用IP 为云厂商未分配可用 IP 数」。
- AC-006：Given 某子网可用 IP 为 0，When 展开下拉，Then 显示 `可用IP: 0`，且仍可选可提交。
- AC-P01：展开下拉后选项在 3 秒内完成渲染（P95 ≤ 3 秒）。

## 6. 边界范围

**本期包含**：
- 资源申领界面与未生产需求调整界面的子网下拉内联可用 IP；
- 异常降级为"查询失败"；
- 口径注明。

**本期不包含**：
- 扩容 / 变配等其他界面；
- IP 预警、不足时拦截提交、自动推荐网段；
- 公有云 / 非自研云子网。
