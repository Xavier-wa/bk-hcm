## 1. 背景与目标

HCM Agent 对话里，用户没有低成本表达「这一轮回复是否有用」的入口。父需求把观测拆成三件互不重叠的事：基础指标上报、用户主动反馈、模型被动反馈。

本迭代只做其中「用户主动反馈」的**前端采集**：在全部 AI Agent 对话场景里，对每一轮已结束的 Agent 回复提供常驻 👍 / 👎，让使用者零摩擦地留下信号。

不做结束后整段对话弹窗打分；不做 HCM 内运营看板 / 监控 / 模型评估展示。

---

## 2. 用户与场景

| 角色 | 诉求 |
| --- | --- |
| Agent 使用者 | 对每一轮回复点赞或点踩，低成本表达该轮是否有用 |
| 值班 / 运营 / 质检 | 本迭代不在 HCM 前端提供看板；他们消费的汇总不依赖本前端页面 |

覆盖范围：**全部** AI Agent 对话场景（主机申领、查询、咨询等），全页对话与浮窗对话只要出现 Agent 回复，均适用。

---

## 3. 功能需求点

### F-001 常驻 👍 / 👎 入口

- 每条 Agent 回复对应的工具栏上**常驻**展示 👍 与 👎（与现网对话组件一致）。
- 按**每一轮回复**采集，不打断对话。
- 不做「整段对话结束后弹窗：打分 / 是否解决问题」。
- **出现时机、流式进行中是否可点、灰态/高亮**：全部跟随对话组件 chat-x 的既有反馈能力，不另定规则。

### F-002 点赞 / 点踩交互（跟随 chat-x）

用户确认：§6 原 Q1–Q5 **一律跟随 chat-x**，不再使用 TAPD 正文里「仅点踩出面板 / 单选 chips / 3 秒撤销 / 就地展开」等与组件不一致的写法。

- 点击 👍 或 👎：按 chat-x 弹出原因收集面板（点赞、点踩都会出面板）。
- 原因标签为**多选**；可再填补充说明。
- 提交：按 chat-x 规则（至少选一个原因，**或**只填补充说明，即可提交）；取消则关闭面板且不保留本次填写。
- 点选后的改选、互斥、撤销、点面板外收起等，均以 chat-x 工具栏 + 反馈面板的既有行为为准，本迭代不新增独立「3 秒撤销」按钮。

### F-003 原因文案（点踩仍用本需求四条）

点踩面板的预设原因使用本需求文案（作为 chat-x 原因列表内容，仍为可多选标签）：

1. 问题理解错误（答非所问 / 曲解意图）
2. 回答数据错误（信息不准 / 过时）
3. 回答不完整（未完成任务 / 缺少关键步骤）
4. 回答不专业（表述混乱 / 引导失败 / 不合规）

点赞面板的预设原因跟随 chat-x 默认/现网用法，本迭代不另拟四条。补充说明占位跟随 chat-x。

### F-004 本前端边界

- 本前端只负责使用者侧的采集与即时反馈（高亮、原因面板提交/取消）。
- **不在 HCM 前端**做运营看板、监控大盘或模型评估展示。
- 反馈按「一轮回复一条」采集（产品口径绑定 run）；字段级约定放到 api 阶段。

## 4. 业务规则

- **R-001**：主动反馈覆盖全部 AI Agent 对话场景，不按场景裁剪入口。
- **R-002**：采集粒度是**一轮回复**，不是整段会话。
- **R-003**：已从「对话结束弹窗」改为「每条回复常驻 👍 / 👎」，不再做结束后问卷。
- **R-004**：原因收集与提交/取消规则跟随 chat-x；点踩预设原因用本需求四条文案。
- **R-005**：运营看板独立于 HCM，本期看板只出汇总，**不依赖、不进入**本前端。
- **R-006**：无转人工、不考虑退出步骤、不回算历史（父需求已定，本前端不体现这些能力）。

---

## 5. 验收标准

- **AC-001**：在任一 AI Agent 对话场景，Agent 回复对应工具栏常驻显示 👍 / 👎；展示时机与 chat-x 一致。
- **AC-002**：点击 👍，按 chat-x 弹出原因面板，提交后记录正向反馈。
- **AC-003**：点击 👎，按 chat-x 弹出原因面板，展示 §3 F-003 四条原因（可多选）及补充说明；按 chat-x 规则提交或取消。
- **AC-004**：流式进行中、改选、取消、点面板外等细节与现网 chat-x 反馈行为一致，不验收独立「3 秒撤销」。
- **AC-005**：全页对话与浮窗对话中，只要出现 Agent 回复，均有同等反馈入口。
- **AC-006**：HCM 内不出现运营看板 / 监控 / 模型评估页面或入口（本迭代）。
