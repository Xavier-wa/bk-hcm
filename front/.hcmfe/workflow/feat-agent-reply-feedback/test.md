# feat-agent-reply-feedback 测试清单

> 工作流: `feat-agent-reply-feedback`
> 关联文档: PRD / Design / API / Coding
> 验收口径：以 `coding.md` 已落地行为为准。PRD F-003 / Design「点踩四条写死文案」、TAPD「仅点踩出面板 / 单选 / 3 秒撤销」**未实施**，本清单不验收这些项。

## 验证范围

- 功能边界: 全页与浮窗 Agent 对话里，对每一轮助手回复打开 chat-x 👍/👎；原因 chips 来自 `agent_feedback_tag` 配置；提交走 commit，本会话内再点已选中按钮走 delete；实时流用 `/agui` 的 `runId`，历史会话用 SNAPSHOT 内 `RUN_STARTED` activity 的 `content.runId`。
- 不在范围: HCM 运营看板、监控、模型评估、结束后整段弹窗打分、项目 iconfont、独立 3 秒撤销、刷新后按 `feedback/list` 还原实心图标、改后端。

## 测试环境

- 前端入口: 对应业务的测试环境地址（全页对话 + 浮窗助手各测一遍；由执行人在测试时确认，不把具体域名写入仓库）
- 测试账号: `<test_account>`（需有业务访问权限，能打开 Agent 对话）
- 数据准备:
  - 后端 MR 反馈接口已部署到当前联调/测试环境（commit / delete / config list）
  - 当前业务下 `config_type=agent_feedback_tag` 至少有一套 like / dislike 标签（或准备「details 为空」账号/环境测 P1-05）
  - 至少一条**已结束**的助手回复（实时新发一轮，以及一条可从会话列表打开的历史会话）
  - 异常分支：浏览器 DevTools 对 `.../feedback/commit` 或 `.../feedback/{run_id}` 做失败拦截（或后端预置错误账号），不要依赖线上真实故障

## 用例清单

### P0 - 主流程（必测）

| ID | 场景 | 前置 | 操作 | 期望 | 回滚 |
|----|------|------|------|------|------|
| P0-01 | 助手回复结束后出现赞踩（全页） | 已登录，打开全页 Agent 对话，发一条能完成的问题 | 等待本轮回复结束 | 该轮助手消息组工具栏常驻 👍 与 👎；引用 / 分享 / 删除仍不可见 | 无需 |
| P0-02 | 浮窗同样出现赞踩 | 同一账号打开浮窗助手 | 完成一轮助手回复 | 与全页一致，出现 👍 / 👎 | 无需 |
| P0-03 | 点赞打开原因面板 | 全页或浮窗，助手回复已结束 | 点击 👍 | 弹出 chat-x 原因面板；chips 为 like 配置的中文文案（可多选），可填补充说明；不是「点一下立刻提交、无面板」 | 点取消关闭面板 |
| P0-04 | 提交点赞 | 面板已打开 | 选至少一个 like 标签，或只填补充说明，点提交 | Toast「已提交反馈」；👍 呈选中；请求为 `POST .../feedback/commit`，`reaction=like`，`session_id` 为 sessions/list 的 `id`（不是 `session_code`），`run_id` 非空，`tags` 为配置 key（不是中文） | P0-07 取消 |
| P0-05 | 点踩打开原因面板 | 助手回复已结束（可用另一轮，或先取消当前赞） | 点击 👎 | 弹出原因面板；chips 为 dislike 配置的中文文案，不是 TAPD 四条写死文案（除非配置恰好相同） | 点取消 |
| P0-06 | 提交点踩 | 点踩面板已打开 | 选标签和/或补充说明后提交 | Toast「已提交反馈」；👎 选中；commit `reaction=dislike` | P0-07 取消 |
| P0-07 | 再点已选中按钮取消反馈 | 本会话内刚提交成功，按钮仍为选中（实心，tooltip「取消满意/取消不满意」） | 再点**同一个**已选中的 👍 或 👎 | 按钮取消选中；发出 `DELETE .../feedback/{run_id}?session_id=`；不再弹出原因面板提交。chat-x 取消走 Tippy onShow，不发 onAgentFeedback | 无需 |
| P0-08 | 历史会话按 SNAPSHOT run 提交 | 会话列表打开一条含多轮助手回复的历史会话（非仅靠当前页实时流） | 对某一轮已结束回复点赞或点踩并提交 | 提交成功且 `run_id` 为该轮 SNAPSHOT `RUN_STARTED.content.runId`，不是打开历史时外层请求自己的 UUID；历史里的 RUN_STARTED / RUN_FINISHED activity 不作为可见气泡 | 再点取消 |

### P1 - 异常分支（必测）

| ID | 场景 | 前置 | 操作 | 期望 |
|----|------|------|------|------|
| P1-01 | commit 失败 | 拦截 `POST .../feedback/commit` 为 5xx 或业务失败 | 打开面板并提交 | 出现项目全局失败提示；列表/对话内容不变。已知限制：chat-x 仍可能把按钮置为激活（回调在激活之后） |
| P1-02 | 缺少本轮 run_id | 若环境有无 `__runId` 的旧历史气泡则用之；否则跳过并注明 | 打开面板并提交 | Toast「无法提交反馈：缺少本轮对话标识」，不发 commit |
| P1-03 | 赞改踩覆盖 | 本轮已点赞提交成功 | 再点 👎，填原因后提交 | 一次 commit `reaction=dislike`（后端按 run 覆盖）；👎 选中、👍 不再作为当前选中 |
| P1-04 | 取消面板不落库 | 打开赞或踩面板 | 点取消或点面板外关闭（跟 chat-x） | 无 commit / delete；按钮保持打开前状态 |
| P1-05 | 标签配置为空 | 该业务 `details` 为空，或 config 拉取失败（前端会当成空 map） | 点 👍 或 👎 | 无 chips，可只填补充说明后提交；提交 `tags` 可省略 |
| P1-06 | 补充说明超长 | 面板打开 | 输入超过 500 个字符后提交 | 请求体 `comment` 最长 500 字（按字符截断）；提交仍成功 |
| P1-07 | 刷新后不还原实心 | 提交成功后刷新页面或切走再进同一会话 | 观察工具栏 | 👍/👎 为未选中（本迭代不接 list 做 UI 恢复）；再点应打开面板做 upsert，而不是误发 DELETE |
| P1-08 | 流式过程工具栏 | 发送新问题，回复仍在输出 | 观察该轮工具栏 | 可用性完全跟 chat-x（现网常见为流式不可点）；结束后可点 |

### P2 - UI 细节（按需）
