# PRD - aiagent · chatbot 聊天窗模式

> 需求来源: TAPD `https://<TAPD_HOST>/tapd_fe/69995598/story/detail/1069995598135027084`
> 设计稿: Figma `node-id=2097-18867`（业务资源 / chatbot 聊天窗模式）
> 关联需求: req-aiagent-chatbot-window-mode

## 1. 背景

现网 AI 助手目前是**全页形态**（路由 `/business/chatbot`，业务视角首页），用户必须进入专属页面才能与 AI 对话，离开当前业务页面、打断当前操作流。

业界标杆组件 `@blueking/ai-blueking` 提供了**悬浮球 + 聊天窗面板**的形态：用户在任意页面点开悬浮球即可在右侧聊天窗内与 AI 对话，不离开当前页面。该组件因后端 API 契约差异无法直接接入（详见前期评估），但其**产品形态可作为完全参照**。

本需求即在 HCM 内补齐这种「聊天窗模式」，复用现网已有的对话能力，提供与 ai-blueking 一致的悬浮球 + 聊天窗交互体验。

## 2. 目标

- 提供一个**通用的 AI 助手聊天窗**：悬浮球触发、面板内对话，全局可用、不打断当前页面操作。
- 产品形态**对齐 ai-blueking**（悬浮球 + 聊天窗面板）。
- **本迭代只交付「窗体形态」**：会话管理与对话渲染能力**复用现网已有实现**，不新增内容渲染器。
- 落地的**验证场景为「主机申领」**，但窗体本身与场景解耦，形态通用、可复用于后续场景。

## 3. 范围与非目标

### 本迭代范围（In Scope）
- AI 助手悬浮球入口（参照 ai-blueking）。
- 点开后的聊天窗面板：包含会话列表 + 对话区 + 输入区。
- 面板**可拖拽、可调整大小**（完全参照 ai-blueking 默认行为）。
- 聊天窗内复用现网对话能力：会话切换/新建、消息流式输出、工具调用、HITL 人工介入、markdown/表格/表单等现有渲染。
- 聊天窗与全页 `/business/chatbot` **共享同一套后端会话**（同一会话空间，互通）。
- 以**页面级、可配置 / 可导入的通用组件**形式提供：聊天窗作为可复用组件，在接入的页面/布局中按配置挂载使用（形态通用、与场景解耦），具备覆盖全局的能力但由接入方按需启用。
- 与现有全页 `/business/chatbot` **共存**。

### 非目标（Out of Scope，本迭代不做）
- 不做划词唤起（ai-blueking 的 AiSelection/划词弹窗），本迭代仅悬浮球 + 面板。
- 不新增/改造对话内容渲染器（主机申领相关的表单/表格/卡片等由现有渲染能力 + 后端 agent 驱动呈现，前端不为本迭代单独开发新渲染组件）。
- 不下线/重构现有全页 chatbot。
- 不扩展主机申领之外的业务场景内容（仅以主机申领为验证场景）。
- 不改动后端 AI agent 接口契约。

## 4. 用户故事

- US-1 作为平台用户，我希望在**任意页面**通过一个常驻入口（悬浮球）快速唤起 AI 助手，**无需跳转到专属页面**，以便不打断当前操作。
- US-2 作为用户，我希望聊天窗以**面板形态**出现在当前页面之上，包含会话列表与对话区，体验与全页一致地完成多轮对话。
- US-3 作为用户，我希望在聊天窗内能**查看/切换/新建会话**，历史会话可继续。
- US-4 作为用户，我希望聊天窗的对话支持**流式输出、工具调用过程、人工介入(HITL)** 等现网已有能力，行为与全页一致。
- US-5 作为用户（主机申领场景），我希望通过聊天窗完成主机申领相关的多轮交互（如配置确认、申请记录查看等），形态与 ai-blueking 示例一致。
- US-6 作为用户，我希望可以**关闭/再次唤起**聊天窗，关闭后不丢失当前会话上下文。
- US-7 作为用户，当我在**全页聊天**中点击「添加到配置清单」并跳转到**主机申领页面**时，我希望该页面**自动唤起聊天窗**并**打开我刚才那条会话记录**，从而在新页面无缝延续同一段对话上下文（会话共享联动）。

## 5. 功能需求点

1. **悬浮球入口**
   - 参照 ai-blueking 悬浮球形态的常驻入口。
   - 点击唤起聊天窗面板；可关闭面板回到悬浮球态。
2. **聊天窗面板**
   - 形态参照 ai-blueking 聊天窗（标题栏 + 会话列表 + 对话区 + 输入区）。
   - 浮于当前页面之上，不占用/破坏当前页面布局。
   - **可拖拽、可调整大小**（参照 ai-blueking 默认）。
3. **会话管理（复用现网能力，与全页共享会话空间）**
   - 会话列表展示、切换、新建。
   - 复用现网会话数据与生命周期（懒创建、历史回放等）；与全页 chatbot 同一套会话，互通。
4. **对话能力（复用现网能力）**
   - 消息流式输出、工具调用、思维链、HITL 人工介入、markdown/代码/表格/表单渲染。
5. **通用可复用组件（页面级可配置 / 可导入）**
   - 聊天窗以可复用组件形式提供，接入方在页面/布局中按配置挂载；形态通用、与业务场景解耦。
6. **与全页共存**
   - 全页 `/business/chatbot` 保留，两种形态并存。
7. **验证场景：主机申领**
   - 以主机申领场景跑通完整聊天窗交互（参照附图与 Figma）。
8. **会话共享联动（跨形态延续）**
   - 全页聊天中的「添加到配置清单」操作跳转到主机申领页面。
   - 跳转后主机申领页面**自动唤起聊天窗**，并**加载来源会话**（与全页同一会话记录），用户可在聊天窗内延续该对话。
   - 依赖 D3：聊天窗与全页共享同一套后端会话空间。

## 6. 验收标准（AC）

- AC-1 在接入了该组件的页面可见 AI 助手悬浮球，点击可唤起聊天窗面板。
- AC-2 聊天窗面板形态与 ai-blueking 示例一致（标题栏/会话列表/对话区/输入区齐备）。
- AC-3 面板可拖拽、可调整大小。
- AC-4 聊天窗内可新建会话、切换历史会话，并继续多轮对话。
- AC-5 聊天窗内对话具备现网全部能力：流式输出、工具调用展示、HITL 人工介入、markdown/表格/表单渲染，行为与全页一致。
- AC-6 聊天窗与全页共享同一套会话：在一端创建/产生的会话，另一端可见并可继续。
- AC-7 主机申领场景可在聊天窗内完整走通（参照 Figma / 附图）。
- AC-8 关闭聊天窗后再次唤起，当前会话上下文不丢失。
- AC-9 现有全页 `/business/chatbot` 功能不受影响，正常并存。
- AC-10 聊天窗浮层不破坏所在页面的原有布局与交互。
- AC-11 会话共享联动：在全页聊天中点击「添加到配置清单」跳转到主机申领页面后，该页面自动唤起聊天窗，并加载来源会话记录，用户可在聊天窗内继续该会话。

## 7. 已确认决策

- D1 面板**可拖拽、可调整大小**，完全参照 ai-blueking 默认行为。
- D2 **不做划词唤起**，本迭代仅悬浮球 + 面板。
- D3 聊天窗与全页 chatbot **共享同一套后端会话**（同一会话空间，互通）。
- D4 悬浮球/聊天窗以**页面级、可配置 / 可导入的通用组件**形式提供，接入方按需挂载；具备覆盖全局的能力但不强制注入各布局。
- D5 本迭代**仅做窗体形态（shell）**，对话内容渲染复用现网能力；**仅以主机申领为验证场景**，但产品形态通用。
